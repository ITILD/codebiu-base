### 2.2 连接后端

| 场景 | 服务器地址（App 内「设置 → 服务器连接」修改） |
| :--- | :--- |

修改后点「保存并测试连接」做连通性校验（探测 `/authorization/auth/register-config`）。Android 已开 `usesCleartextTraffic`、iOS 已配 ATS，允许 HTTP 局域网地址。

## 3. 目录结构

目录结构与 Web 端 [vue3/src](../../../../frontend/vue3/src) 对齐：**一个后端业务域 = 一个模块**，模块内部按 `api / types / providers / pages` 分层；跨模块基础设施集中在 `common/`。

```text
flutter/
├── lib/
│   ├── main.dart                     # 入口：初始化 AppCore
│   ├── app.dart                      # MaterialApp + 主题 + PhoneShell + MultiProvider
│   ├── common/                       # 跨模块基础设施（不含业务页面）
│   │   ├── app_core.dart             # 组合根：Dio + 设置 + 会话 + 各模块 api
│   │   ├── constants.dart            # 默认服务器地址、限宽等常量
│   │   ├── settings.dart             # 地址/AI 模式/模型/主题持久化
│   │   ├── theme.dart                # 主题（明暗）+ PhoneShell
│   │   └── services/                 # api_error / auth_interceptor / local_assistant
│   └── modules/
│       ├── authorization/            # 认证与用户中心
│       │   ├── session.dart          # 令牌与当前用户存储
│       │   ├── api/auth_service.dart
│       │   ├── types/                # auth.dart / user.dart
│       │   ├── providers/auth_provider.dart
│       │   └── pages/                # login / register / password / profile / profile_edit
│       ├── ai/                       # AI 对话
│       │   ├── api/ai_service.dart
│       │   ├── types/                # chat_message / conversation / model_config
│       │   ├── providers/chat_provider.dart
│       │   └── pages/                # chat_page / model_picker_page
│       ├── agent/                    # 智能体
│       │   ├── api/agent_service.dart
│       │   ├── providers/agent_provider.dart
│       │   └── pages/agent_page.dart
│       ├── rag/                      # 知识库
│       │   ├── api/rag_service.dart
│       │   ├── types/kb_project.dart
│       │   ├── providers/rag_provider.dart
│       │   └── pages/                # knowledge_page / kb_project_page
│       └── main/                     # 应用级页面
│           └── pages/                # auth_gate / settings_page
├── android/ ios/ linux/ macos/ windows/   # 平台壳
│   ├── android/app/src/main/AndroidManifest.xml  # 网络权限 + 明文传输 + 应用名
│   ├── linux/runner/my_application.cc    # 桌面窗口 420×880
│   ├── windows/runner/main.cpp           # 桌面窗口 420×880
│   └── macos/Runner/MainFlutterWindow.swift # 桌面窗口 420×880
├── test/                   # 单元测试（本地助手、provider、模型解析）
├── doc/                    # 本目录文档
├── pubspec.yaml            # 依赖：dio / provider / shared_preferences（保持精简）
└── analysis_options.yaml   # flutter_lints 规则集
```

### 3.1 与 Vue3 / 后端的模块对应

| 本客户端 `lib/modules/` | Vue3 `src/modules/` | 后端 `src/` |
| :--- | :--- | :--- |
| `authorization/`（含用户中心） | `authorization/` | `module_authorization` |
| `ai/` | `ai/` | `module_ai` |
| `agent/` | `agent/` | `module_agent` |
| `rag/` | `rag/` | `module_rag` |
| `main/`（登录门、设置） | `main/` | — |

子目录含义一一对应：`api`（接口调用）、`types`（数据类型）、`pages`（页面）、`providers`（状态，对应 Vue3 的 Pinia `stores`）、`components`（模块内组件，当前无，按需新建）。Vue3 的 `utils/styles` 在 Flutter 端分别由 `common/services/` 与 `common/theme.dart` 承担。

> 只创建有代码的模块与目录；Flutter 端暂无 contact / file / task 等模块界面。

## 4. 分层方案

单个模块内四层单向依赖：`pages → providers → api → types`，跨模块共用代码走 `common/`。`api` 与 `types` 不反向依赖上层。**没有第二个依赖方向，没有循环依赖。**

```text
┌──────────────────────────────────────────────────────────────┐
│ pages/（界面层）   modules/<模块>/pages/*.dart                │
│  只做：布局、交互、Consumer/watch 状态、路由跳转、SnackBar      │
│  禁止：直接调 dio、直接读写 SharedPreferences、写业务判断       │
├──────────────────────────────────────────────────────────────┤
│ providers/（状态层） modules/<模块>/providers/*.dart          │
│  只做：聚合 api 调用、持有可变状态、notifyListeners             │
│  禁止：import flutter 的 Widget 库（material.dart）、直接发 HTTP│
├──────────────────────────────────────────────────────────────┤
│ api/（服务层）    modules/<模块>/api/*_service.dart           │
│  只做：一个类对应一个后端域；组请求/解响应/维护会话              │
│  依赖：dio（由 AppCore 注入）、本模块 types、common/services    │
├──────────────────────────────────────────────────────────────┤
│ types/（模型层）  modules/<模块>/types/*.dart                 │
│  只做：纯数据类 + fromJson/toJson，无任何 IO                   │
└──────────────────────────────────────────────────────────────┘
        ↑ 以上四层之外：common/（主题、设置、常量、拦截器、错误中文化、AppCore）
```

### 4.1 各层职责与代表文件

| 层 | 目录 | 职责 | 代表文件 |
| :--- | :--- | :--- | :--- |
| 界面层 | `modules/*/pages/` | 页面/对话主界面；状态只读，动作全走 provider 方法 | `modules/ai/pages/chat_page.dart`、`modules/authorization/pages/login_page.dart` |
| 状态层 | `modules/*/providers/` | ChangeNotifier；暴露状态字段 + 动作方法（login/send/…） | `modules/authorization/providers/auth_provider.dart`、`modules/ai/providers/chat_provider.dart` |
| 服务层 | `modules/*/api/` | 每域一个 Service；只说 HTTP 不说 UI | `modules/ai/api/ai_service.dart`、`modules/rag/api/rag_service.dart` |
| 模型层 | `modules/*/types/` | 纯数据类、枚举、fromJson/toJson | `modules/authorization/types/user.dart`、`modules/ai/types/model_config.dart` |
| 基础设施 | `common/` | 主题/设置/常量/拦截器/错误处理/组合根 | `common/app_core.dart`、`common/theme.dart` |

### 4.2 关键机制（改前必懂）

1. **组合根**：`AppCore.create()` 在 `main()` 构建，持有 `dio/settings/session/auth/ai/rag/agent`；页面永远 `context.read<AuthProvider>().core.xxx` 取服务，**不用第三方 IoC**。`common/app_core.dart` 是唯一允许同时 import 多个模块 `api` 的文件。
2. **令牌刷新**：`common/services/auth_interceptor.dart` 是 `QueuedInterceptor`——401 时用 refresh token 换新 access 并重放原请求；刷新失败才清会话（`modules/authorization/session.dart`）。**改认证接口先读它**。
3. **SSE 流式**：`modules/ai/api/ai_service.dart` 的 `streamChat` 手写解析 `data: {"status":..., "content":...}` 行协议；流式失败自动回退非流式（`chat()`）。后端协议升级时只改这一个文件。
4. **离线助手**：`common/services/local_assistant.dart` 纯函数无 IO，规则与递归下降数学解析器都在内，可独立单测。
5. **宽屏适配**：`MaterialApp.builder` 套 `PhoneShell`（`common/theme.dart`，>460px 限宽居中）；新页面**禁止**自建宽度逻辑，交给全局壳。
6. **平台差异**：桌面窗口尺寸在三个 runner 里硬编码 420×880，改尺寸三处同步。

### 4.3 数据流示例（发送一条 AI 消息）

```text
ChatPage 输入框 → ChatProvider.send(text)
  ├─ 本地模式 → LocalAssistant.reply → 打字机定时刷新 assistant.content → notifyListeners
  └─ 在线模式 → AiService.streamChat(model_id, history)
                 → SSE chunk 逐段 += content → notifyListeners
界面层 Consumer<ChatProvider> 自动重建气泡；错误进 message.error → 气泡内重试按钮 → retryLast()
```

## 5. 新增页面 / 功能接入清单

### 5.1 新增功能入口（基线约定：对话页即应用入口）

1. 确定归属模块（与后端模块同名），功能页面建在 `lib/modules/<模块>/pages/xxx_page.dart`；无法归属既有模块时新建 `lib/modules/<新模块>/`，并按 `api/types/providers/pages` 建目录（有代码才建）；
2. **新建对话空态的功能卡片**：`modules/ai/pages/chat_page.dart` 的 `_EmptyView._features` 列表加一行（图标、名称、说明、动作 key），并在 `onFeature` 里路由——这是所有新功能的默认入口；
3. 需要常驻入口的，同时加到抽屉 `_HistoryDrawer` 底部功能区；
4. 需要数据 → 同模块内新建/扩展 `types/` + `api/` + `providers/`，**页面不直接发请求**；新 provider 在 `app.dart` 的 `MultiProvider` 注册，新 service 在 `common/app_core.dart` 装配；
5. `flutter analyze` + 手测明暗两套主题 + 桌面宽屏（>460px）检查限宽生效。

### 5.2 新增后端接口对接

1. 响应结构 → 所属模块 `types/` 建 Model（fromJson 忽略未知字段）；
2. 所属模块 `api/` 对应 Service 加方法（路径常量集中在类顶部 `_prefix`）；
3. 状态变化 → 同模块 `providers/` 加动作方法；UI 只调动作方法；
4. 错误展示统一 `apiErrorMessage(e)`，禁止裸抛 toString 给用户。

### 5.3 修改桌面窗口尺寸 / 应用名

窗口尺寸：`linux/runner/my_application.cc`、`windows/runner/main.cpp`、`macos/Runner/MainFlutterWindow.swift` 三处同步。应用名：Android `AndroidManifest.xml` 的 `label`、iOS `Info.plist` 的 `CFBundleDisplayName`、Linux/Windows runner 标题。

## 6. 常见问题

| 现象 | 原因与处理 |
| :--- | :--- |
| 真机连不上服务器 | 手机与开发机不同网段，或后端未监听 0.0.0.0；设置页改地址并「测试连接」 |
| Android 请求直接失败 | 模拟器访问本机后端要用 `10.0.2.2:6666` 而不是 localhost |
| 令牌过期弹登录 | refresh 失效属预期；「设置 → 清除登录信息」可手动重置 |
| 桌面窗口过大/过小 | 拖动可调；默认 420×880 由 runner 决定，见 5.3 |
| `flutter run` 找不到设备 | `flutter devices` 排查；Android 需 `adb` 授权、Linux 需 1.2 工具链 |
