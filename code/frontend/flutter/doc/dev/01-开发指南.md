## 4. 分层方案

四层单向依赖：`ui → providers → core.services → core.models`，`core` 不反向依赖上层。**没有第二个依赖方向，没有循环依赖。**

```text
┌────────────────────────────────────────────────────────────┐
│ ui/（界面层）      lib/ui/pages/*.dart                      │
│  只做：布局、交互、Consumer/watch 状态、路由跳转、SnackBar    │
│  禁止：直接调 dio、直接读写 SharedPreferences、写业务判断     │
├────────────────────────────────────────────────────────────┤
│ providers/（状态层） lib/providers/*.dart（ChangeNotifier）  │
│  只做：聚合 service 调用、持有可变状态、notifyListeners        │
│  禁止：import flutter 的 Widget 库、直接发 HTTP               │
├────────────────────────────────────────────────────────────┤
│ core/services/（服务层）  auth_service / ai_service / …     │
│  只做：一个类对应一个后端域；组请求/解响应/维护会话             │
│  依赖：dio（由 AppCore 注入）、models                         │
├────────────────────────────────────────────────────────────┤
│ core/models/ + core/（模型与基础设施）                       │
│  models：纯数据类 + fromJson/toJson，无任何 IO                │
│  app_core/settings/session：服务定位器与持久化，全局单例        │
└────────────────────────────────────────────────────────────┘
```

### 4.1 各层职责与代表文件

| 层 | 目录 | 职责 | 代表文件 |
| :--- | :--- | :--- | :--- |
| 界面层 | `lib/ui/` | 页面/主题/宽屏壳；状态只读，动作全走 provider 方法 | `pages/login_page.dart`、`theme.dart` |
| 状态层 | `lib/providers/` | ChangeNotifier；暴露状态字段 + 动作方法（login/send/…） | `auth_provider.dart`、`chat_provider.dart` |
| 服务层 | `lib/core/services/` | 每类一个 Service；只说 HTTP 不说 UI | `auth_service.dart`、`ai_service.dart` |
| 模型/基础设施 | `lib/core/` | 数据模型、常量、设置与会话存储、AppCore 单例 | `models/user.dart`、`settings.dart` |

### 4.2 关键机制（改前必懂）

1. **服务定位器**：`AppCore.create()` 在 `main()` 构建，持有 `dio/settings/session/auth/ai`；页面永远 `context.read<AuthProvider>().core.xxx` 取服务，**不用第三方 IoC**。
2. **令牌刷新**：`auth_interceptor.dart` 是 `QueuedInterceptor`——401 时用 refresh token 换新 access 并重放原请求；刷新失败才清会话。**改认证接口先读它**。
3. **SSE 流式**：`ai_service.streamChat` 手写解析 `data: {"status":..., "content":...}` 行协议；流式失败自动回退非流式（`chat()`）。后端协议升级时只改这一个文件。
4. **离线助手**：`local_assistant.dart` 纯函数无 IO，规则与递归下降数学解析器都在内，可独立单测。
5. **宽屏适配**：`MaterialApp.builder` 套 `PhoneShell`（>460px 限宽居中）；新页面**禁止**自建宽度逻辑，交给全局壳。
6. **平台差异**：桌面窗口尺寸在三个 runner 里硬编码 420×880，改尺寸三处同步。

### 4.3 数据流示例（发送一条 AI 消息）

```text
ChatPage 输入框 → ChatProvider.send(text)
  ├─ 本地模式 → LocalAssistant.reply → 打字机定时刷新 assistant.content → notifyListeners
  └─ 在线模式 → AiService.streamChat(model_id, history)
                 → SSE chunk 逐段 += content → notifyListeners
界面层 Consumer<ChatProvider> 自动重建气泡；错误进 message.error → 气泡内重试按钮 → retryLast()
```

## 5. 新增页面 / 功能接入清单

### 5.1 新增功能入口（基线约定：对话页即应用入口）

1. 功能页面建 `lib/ui/pages/xxx_page.dart`；
2. **新建对话空态的功能卡片**：`chat_page.dart` 的 `_EmptyView._features` 列表加一行（图标、名称、说明、动作 key），并在 `onFeature` 里路由——这是所有新功能的默认入口；
3. 需要常驻入口的，同时加到抽屉 `_HistoryDrawer` 底部功能区；
4. 需要数据 → 新建/扩展 `providers/` + `core/services/`，**页面不直接发请求**；
5. `flutter analyze` + 手测明暗两套主题 + 桌面宽屏（>460px）检查限宽生效。

### 5.2 新增后端接口对接

1. 响应结构 → `core/models/` 建 Model（fromJson 忽略未知字段）；
2. `core/services/` 对应 Service 加方法（路径常量集中在类顶部 `_prefix`）；
3. 状态变化 → provider 加动作方法；UI 只调动作方法；
4. 错误展示统一 `apiErrorMessage(e)`，禁止裸抛 toString 给用户。

### 5.3 修改桌面窗口尺寸 / 应用名

窗口尺寸：`linux/runner/my_application.cc`、`windows/runner/main.cpp`、`macos/Runner/MainFlutterWindow.swift` 三处同步。应用名：Android `AndroidManifest.xml` 的 `label`、iOS `Info.plist` 的 `CFBundleDisplayName`、Linux/Windows runner 标题。

## 6. 常见问题

| 现象 | 原因与处理 |
| :--- | :--- |
| 真机连不上服务器 | 手机与开发机不同网段，或后端未监听 0.0.0.0；设置页改地址并「测试连接」 |
| Android 请求直接失败 | 模拟器访问本机后端要用 `10.0.2.2:6666` 而不是 localhost |
| 令牌过期弹登录 | refresh 失效属预期；「设置 → 清除登录信息」可手动重置 |
| 桌面窗口过大/过小 | 拖动可调；默认 420×880 由 runner 决定，见 5.3 |
| `flutter run` 找不到设备 | `flutter devices` 排查；Android 需 `adb` 授权、Linux 需 1.2 工具链 |
