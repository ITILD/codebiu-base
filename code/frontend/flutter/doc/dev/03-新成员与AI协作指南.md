# 03-新成员与 AI 协作指南（flutter 客户端）

> 面向两类读者：**新入职员工**（第 1~3 节）与 **AI 辅助开发**（第 4~6 节）。全局工作流（需求登记 → 批准 → 开发 → 交付）见根 [README_AI.md](../../../../../README_AI.md)。

## 1. 新员工第一天：跑起来

```bash
# 1. 环境（一次性，见 01-开发指南第 1 节）
export PATH="/home/hrzn/flutter/bin:$PATH"
flutter doctor          # 确认无 ✗
# 2. 起后端（Docker 环境或本机 server_py，见后端文档）
# 3. 起客户端
cd code/frontend/flutter && flutter pub get && flutter run -d linux
# 4. 登录 admin/admin123（后端 config.yaml 默认管理员）→ 发一条消息 → 切本地模式再发一条
```

**第一天的验收标准**：能登录、能在线对话（SSE 打字效果）、能切本地模式、能改服务器地址、能明暗主题切换。

## 2. 新员工第一周：读懂六个文件

按序通读，读完即可承接小需求：

| 顺序 | 文件 | 学到什么 |
| :--- | :--- | :--- |
| 1 | `lib/main.dart` + `lib/core/app_core.dart` | 应用如何组装、服务如何注册 |
| 2 | `lib/ui/pages/login_page.dart` | 页面写法：表单、provider 调用、错误提示 |
| 3 | `lib/core/services/auth_service.dart` | 一个 Service 的完整样子：请求、解析、会话写回 |
| 4 | `lib/core/services/auth_interceptor.dart` | 令牌刷新机制（最容易踩坑） |
| 5 | `lib/providers/chat_provider.dart` | 状态层写法：动作方法 + 两种回复流（在线/本地） |
| 6 | `lib/ui/pages/chat_page.dart` | 复杂 UI：列表、气泡、输入栏、自动滚动 |

同时读规范：[02-代码规范](02-代码规范.md)（硬规则 12 条）→ 根 [开发流程](../../../../../doc/03-规范/开发流程.md)。

**练手任务（从易到难）**：
1. 「我的」页加一项「复制用户 ID」；

## 3. 新人常见坑

| 坑 | 说明 |
| :--- | :--- |
| 页面里直接 dio 请求 | 打回。一律走 service → provider → 页面 |
| await 后直接用 context | 加 `if (!mounted) return;` |
| watch 和 read 混用 | build 里 `watch`（要重建），回调里 `read`（不重建） |
| 颜色写死 `Colors.blue` | 用 `colorScheme.primary`，深色主题会糊 |
| 改了 linux 窗口忘了 windows | 桌面三平台同步改 |
| 真机连不上 | 设置页改服务器地址为开发机 IP；模拟器用 10.0.2.2 |

## 4. AI 辅助开发：任务拆解原则

AI（Claude/Copilot/Trae 等）在本项目**必须按分层逐层下任务**，禁止一句话「加一个 XX 功能」直接生成全部代码：

```text
正确姿势（自上而下逐层验收）：
需求 → ① models（数据形状）→ ② service（接口方法）→ ③ provider（状态与动作）
     → ④ page（界面）→ ⑤ 联调 + analyze/test

错误姿势：
「帮我写一个收藏功能」→ 一次性生成跨层大文件 → 分层混乱、无法单测
```

给 AI 的任务描述模板：

```text
【层】core/models 或 core/services 或 providers 或 ui/pages
【上下文】参考既有文件 X 的写法（给出路径）
【输入/输出】明确字段、接口路径、状态变化
【约束】遵守 doc/dev/02-代码规范.md 硬规则 N、N；
【验收】flutter analyze 0 issue；flutter test 通过；手动验证步骤…
```

## 5. AI 开发的验收清单（每次改动必过）

1. `flutter analyze` → 0 issue（含 info）；
2. `flutter test` → 全绿；新增纯逻辑（模型/解析/助手规则）必须带单测；
3. 分层检查：`grep -r "dio" lib/ui/ lib/providers/` 无命中；`grep -r "material.dart" lib/providers/` 无命中；
4. 双主题检查：亮色 + 暗色各过一遍改动页面；
5. 宽屏检查：窗口拉宽 >460px，内容仍居中限宽、无横向滚动条；
6. 涉及平台壳（窗口尺寸/权限/应用名）：三平台文件同步；
7. 后端联调：改了 API 对接时用真实后端跑通（登录 → 动作 → 错误分支）。

## 6. 典型改动 SOP（AI 与新员工通用）

### 6.1 新增一个后端能力（例：收藏对话）

| 步 | 层 | 动作 |
| :-- | :-- | :-- |
| 1 | `core/models/` | `favorite.dart`：字段 + fromJson/toJson（+ 单测） |
| 2 | `core/services/` | `ai_service.dart` 加 `listFavorites/addFavorite`（路径常量置顶） |
| 3 | `providers/` | `chat_provider.dart` 加状态 `favorites` + 动作 `toggleFavorite()` |
| 4 | `ui/pages/` | 聊天页 AppBar 加按钮，回调 `context.read<ChatProvider>().toggleFavorite()` |
| 5 | 验收 | 第 5 节清单全过 |

### 6.2 新增一个页面（例：关于页）

| 步 | 动作 |
| :-- | :-- |
| 1 | `ui/pages/about_page.dart`：Scaffold + AppBar，纯展示直接写 |
| 2 | 入口挂载：`profile_page.dart` 的「应用」区加 ListTile → `Navigator.push` |
| 3 | 验收：明暗主题 + 宽屏限宽 + analyze |

### 6.3 升级依赖 / Flutter SDK

1. 改 `pubspec.yaml` 版本 → `flutter pub get`；
2. 全量验证：analyze + test + `flutter build linux --release` + `flutter build apk --debug`；
3. `doc/tag_doc/version_info.md` 记一行变更。

### 6.4 后端接口变更（如登录加字段）

1. 改 `auth_service.dart` 请求体 → 若响应结构变，同步 `models/auth.dart`；
2. 拦截器/会话若受影响，重点回归：过期刷新、登出吊销两条链路；
3. 联调用真后端验证 401 → 刷新 → 重放。

## 7. AI 硬规则速览（详见 README_AI.md）

1. 不新增状态管理方案，不加 UI 组件库，不加路由库（Material 内置够用）；
2. `pubspec.yaml` 增依赖需在提交说明中给出理由与替代方案对比；
3. 生成代码必须过 analyze 0 issue 才算完成；
4. 不修改 `analysis_options.yaml` 降低 lint 等级；
5. 文件超 500 行考虑按 01-开发指南分层拆分；拆分时保持层归属不变。
