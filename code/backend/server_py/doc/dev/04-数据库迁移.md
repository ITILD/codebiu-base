# 数据库迁移（Alembic）

> 目标：**不同版本之间可重复、可审计地升级关系库结构**。后端配置与首启初始化见 [03-配置与初始化](03-配置与初始化.md)，运维执行见 [deveops/版本升级与数据库迁移](../../../../../deveops/运维手册/版本升级与数据库迁移.md)。

## 1. 机制总览

| 阶段 | 行为 | 代码位置 |
| :--- | :--- | :--- |
| 全新库首启 | `create_all` 建立全量表 → 自动 `alembic stamp head` | [`lifespan.py`](../../src/common/config/lifespan.py)、[`migration.py`](../../src/common/utils/db/migration.py) |
| 已有库启动 | 只建缺失表；已有 `alembic_version` 时**不 stamp、不升级** | 同上 |
| 结构演进 | 开发者生成增量脚本，人工审查后提交 | `alembic/versions/` |
| 部署升级 | 停写/备份 → `alembic upgrade head` → 启动新版本 | 运维流程 |
| 回退 | 优先回滚应用 + 恢复备份；Alembic downgrade 仅限有可靠 `downgrade()` 的版本 | 运维流程 |

核心约定：

- **基线版本 `0001_baseline` 是空迁移**：结构由 `create_all` 建立，基线只用于“打标起点”。
- **启动期绝不自动 upgrade**：避免多 worker 竞争、长事务拖慢启动、失败后服务半可用。
- **迁移脚本与服务共用同一份配置**：`alembic/env.py` 从 `config.yaml + config.dev.yaml + CODEBIU_*` 解析 `db_rel`，迁移库与运行库不会不一致。
- **只覆盖关系库**：PostgreSQL。缓存(Redis)、向量库（Milvus）结构不在 Alembic 管理范围。

## 2. 目录与命令

```text
code/backend/server_py/
├── alembic.ini                 # script_location / 文件命名规则
└── alembic/
    ├── env.py                  # 从主服务配置解析连接串；导入 app 注册全部模型
    ├── script.py.mako
    └── versions/
        ├── 0001_baseline.py
        └── 0002_user_preference.py
```

**所有命令必须在 `server_py` 目录执行**（`alembic.ini` 与 `config.yaml` 都在该目录）：

```bash
cd code/backend/server_py

uv run alembic current            # 当前库版本
uv run alembic heads              # 代码中的最新版本（应只有 1 个 head）
uv run alembic history --verbose  # 版本链
uv run alembic upgrade head       # 升级到最新
uv run alembic upgrade +1         # 只前进一步
uv run alembic downgrade -1        # 回退一步（脚本需实现 downgrade）
uv run alembic stamp head         # 只改版本标记，不执行 DDL
uv run alembic revision --autogenerate -m "add_xxx"
```

## 3. 四类场景

### 场景 A：全新数据库

1. 创建空库（PostgreSQL 需手工 `CREATE DATABASE`）。
2. 保持 `state.check_db: true`，启动服务。
3. 服务 `create_all` 建全量表，并自动 `stamp head`。
4. 校验：`uv run alembic current` 应显示 `head`；无需手工 `upgrade`。

### 场景 B：已有库首次接入 Alembic

适用于“表已存在，但没有 `alembic_version`”的旧库：

```bash
cd code/backend/server_py
uv run alembic stamp head        # 以当前代码结构作为基线，不执行 DDL
uv run alembic current
```

> 先确认旧库结构确实与当前模型一致；否则应先补差异脚本，再 stamp。

### 场景 C：开发期修改表结构

```bash
# 1. 修改 do/ 下的 SQLModel 模型
# 2. 生成增量脚本（连接的是 config 指向的库）
uv run alembic revision --autogenerate -m "add_user_preference"

# 3. 人工审查 alembic/versions/xxxx_add_user_preference.py：
#    - 是否只包含预期变更（避免误捕获临时表/索引）
#    - 是否有数据回填、默认值、NOT NULL 兼容
#    - 大表变更的锁行为与耗时评估
#    - downgrade 是否可执行

# 4. 在本地库执行并验证
uv run alembic upgrade head

# 5. 回归测试后，脚本随代码提交
```

注意：

- `--autogenerate` **只比较模型与库结构**，不生成数据迁移；数据回填需手写 `op.execute(...)`。
- 新增 `NOT NULL` 列必须给默认值或分两步（先可空 → 回填 → 收紧）。
- 索引/约束命名保持稳定，避免重复创建。
- 不要手改已发布的迁移脚本；修正应新增一个版本。

### 场景 D：生产环境从版本 A 升级到版本 B

```bash
# 0. 记录当前版本、备份
cd code/backend/server_py
uv run alembic current
pg_dump -Fc -f backup_before_$(date +%F_%H%M).dump "$DB_URL"

# 1. 停写（停应用或进入维护模式），确保无并发写入
# 2. 部署版本 B 的代码（先不启动服务）
# 3. 执行迁移（一次性升级经过所有中间版本）
uv run alembic upgrade head

# 4. 校验
uv run alembic current           # = heads
# 5. 启动版本 B 服务；生产建议 state.check_db=false
```

**跨多个版本**：`upgrade head` 按 `down_revision` 链依次执行 A→A+1→…→B，无需逐版本手工执行。
**跨版本回退**：优先“回滚应用 + 恢复备份”；`downgrade` 只适用于明确实现且无破坏性数据丢失的版本（如 `0001_baseline` 的 `downgrade` 为空，不能用于回空库）。

## 4. 多版本协作规则

1. **版本链保持单 head**：新脚本的 `down_revision` 指向当前 head；合并前先协调，避免多个 head。
2. **已发布脚本不可修改**：线上执行过的脚本视为只读；修正走新版本。
3. **版本号可读**：文件模板 `版本号_含义slug`，建议顺序号 `0003_xxx`，与 `revision` 一致。
4. **一个版本只做一类变更**：结构变更与大批量数据回填尽量拆分，便于回滚定位。
5. **发布记录绑定**：版本说明中记录 `alembic revision`（见 [tag_doc/version_info.md](../tag_doc/version_info.md)）。
6. **多实例部署**：迁移只由发布流水线执行一次，实例启动时 `check_db=false`，禁止每个实例都跑 `upgrade`。

## 5. 迁移与应用启动的关系

| `state.check_db` | 建表 | stamp | 初始化钩子 | 适用 |
| :--- | :--- | :--- | :--- | :--- |
| `true`（默认） | 建缺失表 | 全新库自动 | 执行 | 开发 / 全新部署 |
| `false` | 跳过 | 跳过 | 跳过 | 生产（结构已由 Alembic 准备好） |

> `check_db=false` 时**必须先执行 `alembic upgrade head`**，否则新代码访问新表/新列会失败。

## 6. 检查清单

- [ ] `uv run alembic heads` 只有一个 head
- [ ] `uv run alembic current` 与部署版本要求一致
- [ ] 迁移脚本经过人工审查，含必要的 `downgrade`
- [ ] 生产升级前已备份，且停机/停写
- [ ] 升级后启动日志无建表/迁移告警
- [ ] 版本记录已登记 `alembic revision`
- [ ] 向量库/缓存变更另有重建说明（不在 Alembic 内）
