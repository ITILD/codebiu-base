# 配置与初始化（后端）

> 本文是后端**配置加载、首启初始化、管理员与种子数据、重置与排错**的唯一说明。部署操作见 [deveops/配置与数据库初始化](../../../../../deveops/运维手册/配置与数据库初始化.md)，表结构升级见 [04-数据库迁移](04-数据库迁移.md)。

## 1. 配置分层

优先级从低到高加载（[`common/config/index.py`](../../src/common/config/index.py)）：

| 层级 | 文件 | 是否入 git | 用途 |
| :--- | :--- | :--- | :--- |
| 基线层 | `config.yaml` | 是 | 零依赖默认值 + 引导配置 + `to set real key` 占位 |
| 覆盖层 | `config.**.yaml`（默认 `config.dev.yaml`） | 否（gitignored） | 真实数据库地址、模型密钥、管理员初始密码 |
| 环境变量 | `CODEBIU_*` | — | 容器/K8s 注入，键级最高优先级 |

规则：

1. 覆盖层由 `config.local_file` 指定；**文件被指定但不存在会直接报错**，防止静默回退基线。
2. 嵌套键用双下划线映射：`CODEBIU_TOKEN__SECRET_KEY` → `token.secret_key`。
3. 所有路径相对**启动目录** `server_py` 解析，必须在 `server_py` 目录启动。
4. Linux/macOS 部署时，把基线里 Windows 风格路径（如 `temp_source\db\data.db`）改为 `temp_source/db/data.db`，或在覆盖层重写 `db_rel.database` / `db_cache.database`。
5. **严禁把真实密钥写入 `config.yaml`**；只放 `config.dev.yaml` 或环境变量。

### 全新环境的两种做法

```yaml
# 做法 A（推荐）：保留覆盖层
config:
  local_file: config.dev.yaml
```

```bash
cp config.dev.yaml.example config.dev.yaml   # 若无示例，按需新建最小覆盖文件
```

```yaml
# 做法 B：只跑基线（SQLite + Fakeredis）
config:
  local_file: ""        # 或删除该键，加载器会告警并只读基线
```

## 2. 引导配置 vs 业务动态配置

| 类型 | 代表键 | 生效方式 |
| :--- | :--- | :--- |
| 引导配置 | `db_rel`、`server`、`dir`、`mineru`、`middleware` | **始终以 yaml 为准**，改后重启生效 |
| 业务动态配置 | `db_cache`、`db_vector`、`file_system`、`token`、`login_security`、`email`、`sms`、`tasks`、`websearch`、`parser`、`audit`、`admin` | **首启以 yaml 同名节为种子入库**；之后以「系统管理 → 通用配置」页为唯一事实来源，改 yaml 不再生效 |
| 模型种子 | `default_models` | 不属动态配置组；启动时按 `reset_models` 总开关补种「模型配置」表，`false` 时完全保留库中模型 |
| 环境变量 | `CODEBIU_*` | 每次启动覆盖，优先级最高 |

schema 与默认值在 [`common/config/dynamic/schemas.py`](../../src/common/config/dynamic/schemas.py)。新增业务配置组：加 schema + 默认值 → 首启种子 → 配置页自动出现表单。

## 3. 启动初始化时序

入口 [`common/config/lifespan.py`](../../src/common/config/lifespan.py) 的 `server_start()`：

```
init_runtime()
  ① 连接 db_rel（来自 yaml，动态配置中心依赖它）
  ② 建 sys_config 表
  ③ 以 yaml 为种子写入动态配置（幂等，仅在缺失时写）
  ④ 刷新任务引擎参数快照
  ⑤ 连接 cache / vector / graph（来自动态配置）
connect_all()
  runtime 钩子（如 S3 桶不存在自动创建；不受 check_db 影响）
  ── state.check_db = false ──> 到此结束（要求库结构已就绪）
  startup 钩子（如 PostGIS 扩展，必须先于建表）
  create_all()          # 只为缺失的表建表，不会给旧表加列
  stamp_if_fresh()      # 全新库自动 alembic stamp head；已有版本表则跳过
  init 钩子（建表失败也照常尝试，单个失败仅告警）：
    - Casbin 默认策略初始化
    - 默认管理员创建/修复
    - 基础字典补齐
    - 审计中间件注册与过期清理
    - 各模块幂等补列/种子
```

- **启动期只做“建缺失表 + 打迁移基线”，不会自动 Alembic 升级**（避免多 worker 竞争与长事务）。
- `state.check_db=false` 表示库结构已由运维准备，启动跳过建表与初始化钩子；生产升级常用。
- 初始化钩子必须**幂等**：重复启动、多实例启动都不能产生重复数据或报错。

## 4. 首次部署会初始化什么

| 产物 | 说明 |
| :--- | :--- |
| 关系库表 | `create_all` 建立全部模块表；不会自动创建 PostgreSQL 数据库本身 |
| `alembic_version` | 全新库自动打到 `head`；存量库保留原版本 |
| `sys_config` | 动态配置种子（来自 `config.yaml` 同名节） |
| 默认管理员 | `admin` 段；已存在则不覆盖密码 |
| 权限策略 | Casbin 默认策略 + 角色/权限同步 |
| 基础字典 | 各模块 `dict_seed` 声明的基础字典，只补缺 |
| 审计 | 审计 sink 注册 + 过期记录清理 |
| 对象存储桶 | `file_system.storage_type=s3` 时，启动自动创建桶 |
| 任务调度 | local 协程调度循环 / Celery worker 各自启动 |

> PostgreSQL 的 **database 必须提前创建**（如 `CREATE DATABASE codebiu;`），应用只建表不建库；SQLite 自动创建 `dir.base_child.db` 下的文件（Linux 下路径反斜杠改 `/`）。

## 5. 默认管理员与密码恢复

- 基线默认：`admin / admin123`（`config.yaml` 的 `admin` 段）；首次启动创建，已存在时不用 yaml 覆盖密码。
- 忘记密码：「系统管理 → 通用配置 → 管理员」打开 `reset_password`，重启一次；恢复为配置里的 `password` 后立即关闭开关并改密。
- 已无法登录配置页：直接改 `sys_config` 的 admin 分组（或临时把 `config.yaml` 指向空库首次启动）后重启。

## 6. 重置与重建

| 场景 | 操作 |
| :--- | :--- |
| 只重置管理员密码 | 在通用配置 → 管理员开启 `reset_password` → 重启 → 关闭并改密；无法登录时直接改 `sys_config` 的 admin 分组 |
| 重建 SQLite 开发库 | 停止服务，删除 `temp_source/db/data.db`（及 WAL/SHM），重启 |
| 重建 PostgreSQL 库 | 停止服务，备份后 `DROP DATABASE` / `CREATE DATABASE`，确认 `state.check_db=true` 后重启 |
| 重置动态配置 | 停服务，清理 `sys_config` 对应分组后重启（以 yaml 重新种子）；或直接在通用配置页改回 |
| 只补缺失表 | 保持 `state.check_db=true` 重启（`create_all` 只建缺失表） |
| 库结构已由 Alembic 管理 | 部署时 `state.check_db=false`，先 `alembic upgrade head` 再启动 |

## 7. 常见问题

| 现象 | 原因 / 处理 |
| :--- | :--- |
| `config.local_file 指定的配置文件不存在` | 新建 `config.dev.yaml`，或把 `config.local_file` 置空 |
| `基线配置文件不存在: config.yaml` | 不在 `server_py` 目录启动；切到该目录 |
| 连接 PostgreSQL 失败 | 库未创建、网络/端口不通、密码含特殊字符未编码；先手工 `psql` 验证 |
| 启动后没有新表 | `state.check_db=false`；改回 `true` 或先执行迁移 |
| 改了 yaml 业务配置不生效 | 该组已入 `sys_config`；改「系统管理 → 通用配置」页 |
| 多实例启动报重复键 | 初始化钩子未做幂等；按第 3 节修正 |
| `alembic stamp 失败` 告警 | 不阻断启动；在 `server_py` 目录手工 `uv run alembic stamp head` |
