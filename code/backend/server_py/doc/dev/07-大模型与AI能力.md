# 大模型与 AI 能力（后端）

> 适用模块：`module_ai`（模型接入）、`module_rag`（知识库问答）、`module_agent`（智能体）、`module_office`（文档解析）。
> 约束：**基础框架只接入在线/外部服务，不内置本地推理、不引入 torch/transformers 等重库**。配置密钥规则见 [03-配置与初始化](03-配置与初始化.md)，模块分层见 [01-开发指南](01-开发指南.md)。

## 1. 能力地图

| 能力 | 模型类型 | 入口 | 说明 |
| :--- | :--- | :--- | :--- |
| 对话 / 流式问答 | `chat` | `module_ai/controller/llm.py` | OpenAI 兼容协议，支持流式 |
| 文本向量化 | `embeddings` | `module_ai/service/llm.py` | RAG 分块入库、检索 |
| 重排序 | `rerank` | `module_ai/service/llm.py` | 召回后精排 |
| OCR | `ocr` | `module_ai/controller/ocr.py` | 图片/文档在线识别 |
| 语音识别 | `asr` | `module_ai/controller/voice.py` | 音视频整段转写 |
| 语音合成 | `tts` | `module_ai/controller/voice.py` | 文本转语音 |
| 生图 | `image` | `module_ai`（OpenAI 兼容 `/images/generations`） | 文生图 / 图生图 |
| 文档解析 | — | `module_office` | 调用 MinerU 外部服务，工厂接口可扩展 |
| RAG 问答 | `chat`+`embeddings`+`rerank` | `module_rag/controller/rag_chat.py` | 意图分析 → 检索 → 重排 → 流式生成 |
| Agent | `chat` | `module_agent/service/runner.py` | 手工 tool-calling 循环 + Skill 注册表 |

## 2. 模型配置

表 `model_config`（`module_ai/do/model_config.py`）：

| 字段 | 说明 |
| :--- | :--- |
| `model_type` | `chat/embeddings/rerank/ocr/asr/tts/image` |
| `server_type` | `openai/dashscope/vllm/ollama/aws`（asr/tts 为 `online`；协议细节放 `extra.protocol`） |
| `scope` | `public` / `dept` / `user` 三级可见范围 |
| `dept_id` | `scope=dept` 时的归属部门 |
| `is_default` | 同类型默认公共模型（唯一） |
| `is_active` | 停用后前端灰色且不可调用 |
| `url` / `api_key` | API 地址与密钥；**密钥只能来自覆盖层/配置页，不入 git** |
| `input_tokens` / `out_tokens` | 上下文/输出上限；向量化模型 `out_tokens` 表示维度 |
| `pay_in` / `pay_out` | 成本估算 |
| `extra` | 其他协议参数（JSON） |
| `check_valid/check_format/checked_at/check_result` | 后台自动校验结果，前端能力标签展示 |

规则：

1. 模型按用户/部门隔离：`public` 所有人可用，`dept` 本部门及以下，`user` 仅本人。
2. 默认模型按类型唯一；调用方不硬编码模型名，统一走 `model_config` 解析。
3. 新增模型优先在「模型配置」页添加并运行能力测试，通过后再设为默认。
4. 模型密钥入库也属敏感信息，导出/备份需脱敏。

## 3. 调用链

### 3.1 LLM 流式对话

```text
controller/llm.py
  → service/llm.py (解析 model_config → LangChain ChatOpenAI 兼容客户端)
  → astream() / invoke()
  → AG-UI 事件流 / SSE 返回前端
```

- 流式统一走 AG-UI 事件协议，前端用 `aguiStream.ts` 消费。
- 超时、重试、温度、`no_think` 等从模型配置读取，不在业务代码写死。
- 业务模块只依赖 `module_ai.service` 的能力契约（`do/capability.py` 的 DTO），不直接引用 LangChain 类型。

### 3.2 RAG 全链路

```text
上传文档 → module_office 解析(MinerU) → 分块 → embeddings 向量化 → 向量库
提问 → 意图分析 → 向量检索(+关键词) → rerank → 组装上下文 → chat 流式回答
```

- 知识库项目/文档/成员/部门授权在 `module_rag` 内校验，不走通用文件权限。
- 向量表继承 `VectorModel`；向量库为 Milvus（`db_vector` 配置）。
- 换 embedding 模型必须重建索引，否则新旧向量维度/语义不一致。

### 3.3 Agent 执行循环

`module_agent/service/runner.py`：

```text
bind_tools → astream → 解析 tool_calls → 执行 Skill → 回填结果 → 续跑（最多 8 轮）
```

- Skill 注册表在 `module_agent/skills/`，增删 Skill 不改循环。
- 新增工具：实现 Skill 并在注册表登记；输入输出用 DTO，不泄漏内部实现。

## 4. 扩展指南

| 场景 | 做法 |
| :--- | :--- |
| 新增模型供应商 | 在 `server_type` 体系内扩展适配；优先复用 OpenAI 兼容协议 |
| 新增模型类型 | 同步改 `ModelType`、`ModelTypeEnum`、前端能力标签、模型测试用例 |
| 新增 AI 能力接口 | `controller/service/dependencies` 同名一条线；DTO 放 `do/`；跨模块只暴露 service 契约 |
| 接入新的解析服务 | 在 `module_office` 工厂注册新实现，不改 RAG 调用方 |
| 新增 Agent Skill | `module_agent/skills/` 实现 + 注册；避免阻塞循环的同步重活 |
| 本地调试模型 | 可用 Ollama/vLLM 以 OpenAI 兼容地址接入；仍不引本地推理重库 |

## 5. 密钥与安全

- `config.yaml` 只放 `to set real key` 占位；真实 key 放 `config.dev.yaml` 或 `CODEBIU_*`。
- 前端不直接持有模型 key，所有调用经后端。
- 模型配置 API 返回时对 `api_key` 脱敏；日志不打印完整 key。
- OCR/ASR/生图等外部服务按“未配置密钥应优雅失败”处理，不阻塞主流程。
