## 5. 文档防冗余规则

**写之前先问三句**：

1. **该不该我写？** → 查 §1 归属层与 §2 主题矩阵，不属于本层就只放一行链接。
2. **别处有没有？** → `rg "关键词" --glob '*.md'` 全仓搜索；已有则以已有文档为唯一来源，改它而不是复制它。
3. **读者能在 1 跳内到达吗？** → 本层导航必须收录；跨层引用必须给出相对路径链接。

**禁止的重复形态**：

- ❌ 同一张"文档分层表"在根 README、`doc/README.md`、三个子项目 `doc/README.md` 各写一份 → 只保留本文件 §1。
- ❌ 快速开始命令在根 README 与子项目 README 各写完整版 → 根 README 只留最小三段并链接。
- ❌ 能力清单在根 README 与总体架构文档各写详尽版 → 根 README 只留概括表。
- ❌ 迁移步骤在「后端 04」与「运维版本升级」里各写一遍 → 后端写"怎么写脚本"，运维写"何时执行/回滚"。
- ❌ 同一规范既写进 `doc/03-规范/代码规范.md` 又搬进各端 `doc/dev/02-*规范` → 通用规范只在 `03-规范`，各端只补本端特有硬规则。

**允许的重复**（属于入口索引，不算冗余）：标题级摘要、跳转链接表、代码入口速查表（各端 `doc/README.md` 独有）。

## 6. 文档维护与门禁

1. **新增文档**：先定归属层 → 落盘 → 在该层导航（§3 或子项目 `doc/README.md`）加一行 → 若跨层影响，在 §1/§2 补归属说明。
2. **移动/重命名**：同步修正所有引用（`rg '旧文件名' --glob '*.md'`），并在登记册「变更记录」记一行。
3. **链接必须相对路径**；文档内图片放 `doc/images/`。
4. **历史不改写**：登记册变更记录保留原文，新增追加末尾。
5. **文档属于豁免变更**：不开需求卡，但必须在登记册「变更记录」记一行。
6. **提交前自检**（AI 与人均适用）：
   - [ ] 新文档已在本文件或所属层导航登记
   - [ ] 未新增跨层重复内容（`rg` 复核关键词）
   - [ ] 所有相对链接可解析（抽查 + `rg` 校验）
   - [ ] 根 README / 子项目 README / 子项目 doc 三者的入口链接一致
   - [ ] 若改动根展示页：`README.md` 与 `README.en.md` 已同步（同级标题、同一批截图、同一组链接）
