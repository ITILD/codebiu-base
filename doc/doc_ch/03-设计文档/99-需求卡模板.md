# 需求卡模板

> **一张卡走天下**：一个需求 = 一张卡 = 登记册一行 REQ + N 行 FEAT。没有第二层卡片。
> 用法：整块复制下方模板到 `03-设计文档/requirements/REQ-<NNN>-<短名>.md` 填写。
> 分工：**全部内容 AI 代填**，人只做一件事——看完说"批准"或提修改意见。

```markdown
# REQ-<NNN>：<需求名>

- 域：BASE | AGENT | CADGIS | NOVEL | <自定义>　　状态：草案
- 提出：<人名/AI>　　日期：<YYYY-MM-DD>　　登记册：已加行 ✅
- 一句话：<给谁用，解决什么问题>

## 1. 功能清单
<!-- AI 拆解；每行 = 一个可独立验收的功能，对应登记册一行 FEAT -->

| 编号 | 功能 | 优先级 | 状态 |
| :--- | :--- | :--- | :--- |
| FEAT-<域>-<NNN> | <功能名> | P0/P1/P2 | 草案 |

## 2. 影响面
<!-- AI 填；让批准的人一眼看到动了什么 -->

- 新增：<module_xxx / modules/xxx 等新文件目录>
- 修改：<既有文件，标注是否触碰公共层 common/module_main/module_authorization>
- 数据：<新表/新字段；无则写"无">
- 依赖：<新增第三方库，须符合"禁 500MB+ 大库"；无则写"无">

## 3. 方案要点
<!-- AI 填，3~6 条 bullet；写粗粒度即可，细节开发时再定 -->

- 表：<表名 + 关键字段>
- 接口：<方法 路径（权限点 域:资源:动作）>
- 页面：<路由 + menu.ts 菜单位置>
- 复用：<模型配置/任务队列/权限/动态配置/文件系统 等既有设施>

## 4. 验收标准
<!-- 批准前必须可勾选；全部 ✅ 才能置「已交付」 -->

- [ ] <命令级/页面级可操作的通过条件>
- [ ] 后端 `import app` 无报错；前端 `pnpm run build` 通过

## 5. 记录

- 批准：<YYYY-MM-DD 用户名>（草案 → 已批准）
- 交付：<YYYY-MM-DD，版本；验收标准已全勾>（已批准 → 已交付）
```

## 填写示例（节选）

```markdown
# REQ-005：小说阅读站

- 域：NOVEL　　状态：草案
- 提出：用户　　日期：2026-10-18　　登记册：已加行 ✅
- 一句话：给大众读者，提供书城浏览与在线阅读

## 1. 功能清单
| 编号 | 功能 | 优先级 | 状态 |
| :--- | :--- | :--- | :--- |
| FEAT-NOVEL-001 | 书籍管理 | P0 | 草案 |
| FEAT-NOVEL-002 | 阅读器页面 | P0 | 草案 |

## 2. 影响面
- 新增：module_novel / modules/novel
- 修改：无（不触碰公共层）
- 数据：新表 novel_book、novel_chapter
- 依赖：无
```

> 简单改动（一两句话能说清）也走同一张卡，只是 1~4 节各写一行即可——**卡宁小勿缺**。
> 状态变更只改卡头部一行 + 第 5 节记录 + 登记册，三处同步。
