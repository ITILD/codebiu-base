### 交付明细

**依赖新增（用户指定组件，npm @file-viewer/vue3@3.2.2）**

- `@file-viewer/vue3`（组件壳 ~700KB unpack）+ `@file-viewer/preset-lite`（text/image/media）+ `@file-viewer/preset-office`（pdf/word/spreadsheet/presentation/ofd）+ devDep `@file-viewer/vite-plugin`（renderer 自动装配 + worker/wasm 资产复制）
- `vite.config.ts`：`fileViewerRenderers({ autoPresets: false, renderers: [image,text,pdf,word,spreadsheet,presentation], copyAssets: true })` **显式限定 6 渲染器**（排除 preset-office 附带的 hangul/iwork/wordperfect 无关重型链路）；`createFileViewerManualChunks()` 与既有 manualChunks 组合，渲染器独立 chunk 不进主包

**后端 module_file（预览授权与内联流）**

- `controller/filesystem.py` 新增 `GET /preview/{entry_id}`：鉴权复用下载判定链 `get_download_user_id`（匿名 401/无权限 403/业务条目走来源模块钩子）；统一服务端流式代理不 302 直链（保证同源 fetch，规避对象存储跨域）；`Content-Disposition: inline` + 文件名 RFC 5987 编码（中文兼容）
- `module_office` 零改动（Office 本地渲染后 MinerU 仅供 rag）

**前端 modules/file**

- `components/FilePreviewDialog.vue`（新）：el-dialog destroy-on-close + FileViewer（theme system 跟随系统）；`open(row)` 内联校验类型白名单/下载权限/大小上限 50MB；`authFetch` 拉预览流 blob → `new File()` 交给组件（组件 `file` prop 原生接受 File/Blob/ArrayBuffer）；双 script 块导出 `isFilePreviewable` 供列表复用
- 白名单：图片 11 种/PDF/Word(docx,docm,doc,dot,rtf,odt)/Excel(xlsx,xlsm,xlsb,xls,csv,tsv)/PPT(pptx,pptm,ppsx——**不含 .ppt 二进制老格式**，其链路内置 16M CJK 字体，收益低体积高)/文本(md,txt,json,xml,yaml,html 等)；白名单外提示"暂不支持在线预览"
- `api/filesystem.ts`：`getFilePreviewPath`；`pages/index.vue`：操作列加"预览"按钮（可预览类型才显示，无下载权限灰显+tooltip）、双击文件直接预览（原忽略改为预览）、挂载对话框

**体积与内存口径（用户全局约束下的取舍，均已注明）**

- 主包零污染：6 个渲染器独立 chunk + 18 个 worker/wasm 资产自托管 dist/vendor（pdf.worker 2.8M/xlsx 1.4M/docx 1.1M/pptx 748K），**全部按需懒加载**——用户预览对应格式才下载，首屏与未预览用户零成本
- 部署磁盘增量约 32M（vendor）+ 预览器 chunk；`.ppt` 老格式已在白名单排除（其 16M CJK 字体资产仍在 vendor 目录但永不触发下载，后续如需可再裁）
- 运行内存：单文档单会话，组件随对话框 destroy-on-close 卸载自动销毁渲染会话（组件生命周期文档保证）；50MB 上限防大文件解析拖垮内存；数据流为二进制 blob 全程无 base64
