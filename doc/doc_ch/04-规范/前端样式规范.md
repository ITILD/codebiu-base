# 前端样式规范

> 适用范围：`code/frontend/vue3`。核心原则：**页面自己的样式写在自己的页面或组件里，优先 UnoCSS 原子类**；全局只保留主题变量（`base.css`）与跨页复用的快捷类（`uno.config.ts`）。
> 断点/字号/按钮/边框等响应式细节见 [响应式自适应规范.md](响应式自适应规范.md)；本文只回答"样式写在哪、怎么写"。

---

## 1. 样式写入位置决策树

新增/修改样式时按顺序判断，**命中即停，不得越级**：

| 顺序 | 判断 | 写法 |
| :--- | :--- | :--- |
| ① 默认 | 单处使用 | 模板内直接写 UnoCSS 原子类（含 attributify 属性写法），如 `class="flex items-center gap-2"` 或 `<div mb-4>` |
| ② 页内复用 | 同一组合在本页面/组件内出现 ≥3 处 | 在 `<script setup>` 定义**类名常量**，模板 `:class` 引用（见 §4） |
| ③ 跨页复用 | 两个及以上页面/模块使用同一组合 | 先查 `uno.config.ts` 的 `shortcuts`/`rules` 是否已有，没有则新增（需中文注释说明用途） |
| ④ 无法原子化 | 命中 §2 白名单场景 | 页面/组件 `<style scoped>`，写在**自己文件**里 |
| ⑤ 主题色 | 新增全局色值 | 先在 `base.css` 建变量，再到 `uno.config.ts` 注册色/快捷类（唯一路径） |

要点：

- **样式跟随组件走**：页面/组件私有的样式（包括白名单 scoped CSS）一律写在本文件内，禁止挪到全局样式文件、父组件或兄弟页面里。
- **方向不可逆**：scoped CSS 里禁止写原子类能表达的布局属性（flex/grid/间距/字号/圆角）；scoped 只写白名单场景的核心效果。
- 已有全局 shortcut 优先复用：`flex-center`、`center`、`mini-text-center-between`、`page-shell`、`page-card`、`card-toolbar`、`note-icon-btn`、`h-app` 等，先查 `uno.config.ts` 再动手。

## 2. `<style scoped>` 白名单场景

只有以下 4 类允许写 scoped CSS（全部以现有代码为例）：

| # | 场景 | 原因 | 现有示例 |
| :--- | :--- | :--- | :--- |
| 1 | `:deep()` 穿透第三方组件内部 | 原子类够不到组件库内部 DOM | `config.vue` 的 `:deep(.el-aside)`；`model_config.vue` 的表格行弱化；`db.vue` 的 `:deep(.el-table .row-active)` |
| 2 | 依赖 JS 状态 class 的激活态 | 运行时切换类名，纯原子类无法表达 | `conversation.vue` 的 `.think-btn.active`（静态部分已原子化到模板） |
| 3 | Vue transition 动画类 | `enter/leave` 类名由 Vue 运行时生成 | `conversation.vue` 的 `.fade-*` |
| 4 | 复杂绘制效果 | mask/filter/clip-path/多级渐变/复杂 keyframes，原子类表达力不足 | `index.vue` 的 `.note-etch`（SVG mask）；`decor/`、`garden/` 特效组件 |

补充约束：

- 白名单场景内，布局属性仍用原子类写在模板上，scoped 只写核心效果（如激活态只写颜色差异）。
- 场景 3 确需非 scoped 的 `<style>` 时（teleport/slot 元素 scoped 命中不了），类名必须带组件语义前缀（如 `fade-`）且注释说明原因，防止全局冲突。
- 不再命中白名单的旧样式应随手迁移为原子类；迁移时保留原中文注释到模板对应位置。

## 3. 主题色双轨制

项目存在两套并行的视觉体系，按页面归属选轨，**禁止写死 hex**：

| 轨道 | 适用页面 | 颜色写法 |
| :--- | :--- | :--- |
| note 笔记风 | toC 主题页（index/template/playground 等） | `--note-*` 变量：`text-note`、`bg-note-card`、`border-note`、`text-note-green`… |
| Element Plus 后台风 | 后台管理页（modules/main、ai、rag 等表格/表单页） | `--el-*` 变量：`text-[var(--el-text-color-secondary)]`、`bg-[var(--el-color-primary-light-9)]`… |

- EP 组件主色已被主题变量覆盖，按钮/标签直接用 `type="primary"` 等，不改写内部样式。
- 圆角：note 页用语义刻度 `rounded-note-sm/md/lg`；EP 后台页可用标准刻度 `rounded-*`（如 `rounded-lg` = 8px），不写 `rounded-[13px]` 这类任意值。
- 阴影/过渡优先复用 `shadow-note`、`note-transition`；EP 页用 `--el-box-shadow-light` 等变量。

## 4. 页内类名常量（决策树 ②）

同一组合在页内复用 ≥3 处时，在 `<script setup>` 顶部集中定义常量，模板 `:class` 引用：

```vue
<script setup lang="ts">
// ===== 页面局部样式组合(UnoCSS 原子类, 仅本页使用) =====
/** 概览统计卡: 弹性占满 + 悬浮阴影 */
const statCardCls
  = 'flex-1 min-w-45 flex items-center gap-3.5 px-5 py-4 bg-[var(--el-bg-color)] border border-solid border-[var(--el-border-color-lighter)] rounded-lg transition-shadow duration-200 hover:shadow-[var(--el-box-shadow-light)]'
</script>

<template>
  <div :class="statCardCls">…</div>
</template>
```

硬性要求：

- **完整类名字符串**：常量值必须是完整原子类字符串，禁止运行时拼接/插值（UnoCSS 提取器扫描源码文本，拼出来的类不会生成 CSS）。
- 一处常量只表达一个语义单元（卡片/图标/标题），不把整段模板类堆进一个常量。
- 常量必须有中文注释说明用途。

## 5. 命名与注释

- scoped 内类名用本页语义小写中划线（`stat-card`、`think-btn`），**禁止通用名**（`.card`/`.title`/`.active` 单独存在）防止意外命中。
- 每个 `<style scoped>` 块开头注释说明"为何保留 scoped"（对应白名单场景编号）；复杂选择器逐条注释。
- 删除元素/功能时同步删除对应样式与模板 class，不留死类（如无定义的 `stat-time`）。

## 6. 禁止事项

- ❌ 新增全局生效的样式类（非 scoped `<style>` 定义通用类）——全局能力只通过 `uno.config.ts` 的 shortcuts/rules 提供
- ❌ scoped CSS 写布局（display/gap/padding/margin/font-size 等原子类可表达项）
- ❌ 写死 hex 色值、px 写正文字号（见响应式规范 §2.1）
- ❌ 滥用 `!important`（仅覆盖 EP 内联样式时允许，须注释原因）
- ❌ 把页面私有样式提取到"公共样式文件"或父组件里（样式归位：谁用谁持有）

## 7. 自查清单（提测前过一遍）

- [ ] 新样式优先尝试了原子类？页内复用 ≥3 处的提成了类名常量？
- [ ] scoped CSS 命中 §2 白名单四场景之一，且块首有注释？
- [ ] 已复用 `uno.config.ts` 既有 shortcut，没有重复造轮子？
- [ ] 颜色走 `--note-*`/`--el-*` 变量，圆角走语义/标准刻度？
- [ ] 类名常量是完整字符串（无拼接、无插值）？
- [ ] 没有新增全局类、没有 `!important`、没有 px 字号？
- [ ] 删除/重命名时清理了对应样式与死类名？
