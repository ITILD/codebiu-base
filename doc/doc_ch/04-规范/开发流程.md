# 开发流程（新功能开发手册）

> 前置：功能已在 [00-需求功能登记册.md](../03-设计文档/00-需求功能登记册.md) 置为「已批准」（见 [需求与功能管理.md](需求与功能管理.md)）。
> 本手册回答「开发时每一步做什么」；代码风格见 [代码规范.md](代码规范.md)，权限细节见 [doc/dev/permission.md](../../backend/server_py/doc/dev/permission.md)。

## Step 1 设计确认

- 对照需求卡确认：数据模型 / 接口 / 页面 / 复用设施，有出入先更新需求卡再动手。
- 复用优先级：模型配置(module_ai) > 任务队列(module_task) > 权限/动态配置 > 文件系统(module_file) > 新造轮子。

## Step 2 后端开发

### 2.1 模块结构（垂直切分，每个业务线五件套齐全）

**每个业务线模块必须具备完整的 controller / service / dao / do / dependencies**（config/tasks 可选），非业务算法放模块 `utils/`：

```
src/module_<业务线>/
├── controller/    # 路由端点(仅参数校验+调 service, 不写业务)
├── service/       # 业务逻辑(唯一写业务的地方, controller/任务共享)
│                  # 复杂跨模块业务 = service 之间互相调用(经模块对外入口, 不挖对方内部文件)
├── dao/           # 数据访问(关系库 SQLModel 查询 / 向量库操作)
├── do/            # 数据对象(SQLModel 表模型 + Pydantic 请求响应体)
├── dependencies/  # FastAPI 依赖注入(分页/鉴权/重依赖惰性加载)
├── utils/         # 非业务算法与纯工具函数(无业务状态, 可被本模块任意层调用)
├── config/        # permissions.py 权限声明 + server.py 模块初始化
└── tasks/         # 任务(有异步任务时)
```

### 2.2 接入清单

1. **路由注册**：`src/app.py` import 区加 controller import（模块 Router 自动挂载，见文件头注释）。
2. **权限声明**：`config/permissions.py` 声明 `域:资源:动作` 权限点，module_main 管理域节点归 module_authorization 声明；启动自动同步 Casbin。
3. **数据表**：SQLModel 模型加 `table=True`；建表由启动流程自动完成（无需迁移脚本，新表首启创建）。
4. **动态配置**（可选）：业务可热更配置加到 `common/config/dynamic/schemas.py`（schema 即表单，前端零改动）。
5. **向量表**（可选）：继承 `VectorModel`（`table=True`），自动进注册表，启动时 `create_all` 自动发现远端未创建的集合并建表（幂等跳过已存在）；注意 Milvus 的 **str 字段必须声明 max_length**（`Field(json_schema_extra={"max_length": N})` 或 MaxLen 元数据）。向量后端按动态配置 `db_vector.type` 路由（milvus 远程主用 / lancedb 本地备选，对应 SDK 按需安装）。
6. **异步任务**（可选）：tasks 目录写任务函数，在 `module_task/tasks/__init__.py` 的 TASK 注册表登记，双引擎（local/celery）自动生效。
7. **验证**：`uv sync` → `python -c "import sys; sys.path.insert(0,'src'); import app"` → 启动 `python src/app.py` 看启动日志无 error → `/docs` 手测新端点。

## Step 3 前端开发

### 3.1 模块结构（页面/组件/API/类型聚合）

```
src/modules/<模块>/
├── api/           # 接口封装(用 common/api/http.ts 的 fetch, 勿裸写 fetch)
├── components/    # 模块内组件
├── pages/         # 页面(自动生成路由)
└── types/         # 类型定义
```

### 3.2 接入清单

1. **路由**：`pages/<p>.vue` 自动生成 `/<模块>/<p>`；无需手写路由。页面主题由 `vite.config.ts` extendRoute 约定（app 主应用 / admin 后台 / standalone 独立页）。
2. **菜单**：`src/app/config/menu.ts` 加菜单项（`perm` 与后端权限点一致；主应用入口加 `mainApp: true`）。
3. **API**：统一走 `common/api/http.ts`（token 注入/401 刷新重试）；流式走 `aguiStream.ts`（AG-UI 协议）。
4. **样式**：UnoCSS 原子类 + 主题 CSS 变量（`--note-*` 淡雅自然笔记风），遵循 [响应式自适应规范.md](响应式自适应规范.md)；组件选型参考 modules/template（element-plus 基础组件 / echarts 图表 / babylonjs 三维）。
5. **验证**：`pnpm dev` 手测 → `pnpm run build`（含 type-check）通过。

## Step 4 联调与交付

- 后端 + 前端联调，逐条过需求卡「验收标准」。
- 有数据变更的补升级步骤；有新依赖确认 `pyproject.toml` / `package.json` 已声明。
- 更新登记册（状态 → 已交付，勾验收标准）与需求卡交付记录；发版则同步前端 `versions.ts`。

## 交付自检清单

- [ ] `src/app.py` 已注册新路由；权限点前后端一致
- [ ] 新表/向量表首启自动创建；动态配置组（如有）schema 已声明
- [ ] menu.ts 菜单/入口卡已加；页面主题 meta 正确
- [ ] `import app` 无报错；`pnpm run build` 通过
- [ ] 登记册与需求卡状态已同步
