# 需求与功能管理

> 规则：**先文档 → 再登记 → 人批准 → 再开发 → 同步交付**。状态不是「已批准」、设计/契约未更新，就不写功能代码。
> 台账：[00-需求功能登记册.md](../02-设计文档/00-需求功能登记册.md)　卡片模板：[99-需求卡模板.md](../02-设计文档/99-需求卡模板.md)
> 配套 Skill：[01-需求登记与批准](../05-开发skill/01-需求登记与批准.md) · [02-三层归类与文档先行](../05-开发skill/02-三层归类与文档先行.md)

## 1. 状态（只有 4 个）

```
草案 ──人批准──→ 已批准 ──过验收──→ 已交付
 └──────────────────→ 已废弃
```

| 状态 | 含义 | 能否开发 |
| :--- | :--- | :--- |
| 草案 | 已登记，卡已填，等人点头 | ❌ |
| **已批准** | 用户明确批准（回复"同意/可以/批准"均算） | ✅ **唯一可开发** |
| 已交付 | 验收标准全部勾选，登记册已同步 | — |
| 已废弃 | 不做了（编号保留不复用） | ❌ |

批准 = 一次对话确认，不要求会议或正式评审文档；卡里的「影响面 / 方案 / 验收标准」即全部评审材料。

## 2. 编号（递增不复用）

| 概念 | 编号 | 说明 |
| :--- | :--- | :--- |
| 需求 REQ | `REQ-<NNN>` | 一次业务诉求 = 一张卡（如 REQ-005） |
| 功能 FEAT | `FEAT-<域>-<NNN>` | 卡内一条可独立验收的功能（如 FEAT-AGENT-001） |

域（全大写缩写）：`BASE` 基线公共 / `AGENT` 智能体 / `CADGIS` 二三维 / `NOVEL` 小说站 / 新场景自定义。

## 3. 日常只有 5 个动作

| 动作 | 谁做 | 怎么做 |
| :--- | :--- | :--- |
| 文档先行 | AI 自动（人可手动） | 按 [三层判定树](../02-设计文档/04-AI能力平台架构设计.md) 归类 → 更新设计/契约文档 → 再填卡登记 |
| 登记 | AI 自动（人可手动） | 复制模板到 `02-设计文档/requirements/REQ-<NNN>-<短名>.md` 填卡 → 登记册加行 |
| 批准 | **人（唯一必做动作）** | 看卡与设计变更 → 回复批准 → 状态改「已批准」（记日期） |
| 开发 | AI / 人 | 按 [开发流程.md](开发流程.md) 实现，遵守 [代码规范.md](代码规范.md) |
| 交付 | AI / 人 | 验收标准逐条勾选 → 同步文档与 `doc-manifest` → 状态改「已交付」→ 卡补交付记录 |

## 4. AI 默认流程

用户提需求 → ① AI 按三层判定树归类，**先更新设计/契约文档**，再填卡 + 登记册加行（草案）→ ② AI 给出功能清单/方案/验收标准，请求批准 → ③ 用户批准，置「已批准」后按《开发流程》开发 → ④ 验收通过，同步设计文档、需求卡与 [`doc/doc-manifest.yaml`](../doc-manifest.yaml)，置「已交付」并补交付记录。

信息不足时先问再登记；用户说"批准"即推进，其余全部 AI 代办。

**AI 禁例**：没登记就写功能代码；设计/契约未更新就开工；替用户批准；验收标准没全过就置「已交付」；在基线公共模块硬编码场景专有逻辑；代码改了但未同步 `@doc-sync` 指向的文档。

## 5. 豁免与基线保护

- **豁免（不占编号）**：缺陷修复、文档更新、纯重构（不改行为）、依赖升级 → 只需在登记册「[变更记录](../02-设计文档/00-需求功能登记册.md)」表加一行，无需开卡。
- **基线保护**：动公共层（`common/`、module_main、module_authorization 等）的需求，卡里必须写明影响面与兼容说明；优先**新增模块/新增文件**扩展场景，不为单场景需求改公共底座。

## 6. 三层归类（需求卡必填）

每个需求在「影响面」中明确写出归类结果，避免把业务逻辑塞进 Model/Skill/Agent：

| 归类 | 判定 | 落地位置 |
| :--- | :--- | :--- |
| **Model** | 模型接入或固定规则函数，不含业务流程 | `model_config` / `module_ai/functions/` |
| **Skill** | 单次、无状态、可复用的执行单元 | `module_xxx/skills/<key>/manifest.py + impl.py` |
| **Agent** | 多步编排、会话角色或固定工作流 | 代码 Manifest / `module_agent/agents/` |
| **业务流程** | 有状态、需事务与权限过滤的领域功能 | `module_xxx/service.py + api.py` |
| **普通 CRUD/展示** | 无复用价值的页面/接口 | Controller + Service，不进入三层 |

## 7. 代码-文档同步

需求交付前必须完成：

1. 代码入口的 `@doc-sync` 标记指向的文档已更新。
2. [doc-manifest.yaml](../doc-manifest.yaml) 中对应 `code → path` 映射与 `sync_triggers` 已更新。
3. 涉及根展示页时，`README.md` 与 `README.en.md` 同批同步。
4. 外部/手工代码按 [03-代码导入与文档回收](../05-开发skill/03-代码导入与文档回收.md) 执行；无法映射到文档的代码不得合入公共底座。
5. 登记册「变更记录」留一行（来源、影响面、同步的文档）。
