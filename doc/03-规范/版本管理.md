# 版本管理

## 1. Git 常用命令

```bash
# 克隆
git clone https://github.com/username/repository.git
# 分支
git checkout -b feature-login  # 创建并切换功能分支
git checkout main
git merge feature-login        # 合并到当前分支
git branch -a                  # 查看所有分支
# 提交与推送
git add .
git commit -m "feat: add new feature"
git commit -am "fix: bug fix"  # 跳过暂存区
git push
git push -u origin feature-login
git pull
# 标签
git tag                        # 查看标签
git tag v1.0.0                 # 轻量标签
git tag -a v1.2.0 -m "User authentication feature"
git push origin v1.2.0
git push origin --tags
# 清理分支
git branch -d feature-login
git push origin --delete feature-login
```

## 2. 项目工作流

1. 从 `main` 拉功能分支开发（分支 `dev` 并行开发，PR 审查后合入 `main`）。
2. 提交信息：`feat|fix|refactor|docs|chore: 中文摘要`。
3. PR 描述包含：修改目的、相关 Issue 编号、测试情况、UI 截图（如有）。
4. 冲突处理：`git fetch` → `git rebase` → 解决后 `git add .` → `git rebase --continue`。
5. 一个 PR 只做一件事；接口变更同步更新文档。

## 3. 应用版本与数据库版本

| 版本 | 位置 |
| :--- | :--- |
| 后端应用 | `code/backend/server_py/pyproject.toml` 的 `version` |
| 前端应用 | `code/frontend/vue3/package.json` 的 `version` |
| 数据库结构 | Alembic `alembic_version` 表 |

1. **数据库只向前演进**：已发布的迁移脚本不可修改，修正走新版本。
2. **应用可回滚，结构回滚优先靠备份**：不要依赖 `downgrade` 做生产回滚。
3. **每个版本记录对应迁移 revision**：写入后端 `doc/tag_doc/tag_<版本>.md`。
4. **发布流程**：备份 → 部署代码 → `uv run alembic upgrade head` → 启动 → 验证。

详见 [版本升级与数据库迁移](../../deveops/运维手册/版本升级与数据库迁移.md) 与 [后端数据库迁移](../../code/backend/server_py/doc/dev/04-数据库迁移.md)。
