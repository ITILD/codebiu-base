# 三层归类与文档先行

## 何时使用

需求已批准，准备进入设计或开发；或用户问「这个功能放哪」「要不要做成 Skill/Agent」。

## 执行步骤

1. **读契约**：读 [04-AI能力平台架构设计](../02-设计文档/04-AI能力平台架构设计.md) 的三层职责与 §2.6 判定树；涉及对话/自动调用时再读 [05](../02-设计文档/05-对话智能体与执行协议设计.md)。
2. **过判定树**（按顺序，命中即停）：

```text
Q1 是模型接入或固定规则函数，且不含业务流程？        → Model
Q2 是单次、无状态、可被页面/对话/任务复用的执行单元？ → Skill
Q3 需要多步编排、计划、会话上下文或固定工作流？       → Agent
Q4 有状态、需事务/权限过滤/领域规则？                 → 业务流程（Service）
Q5 只是页面/接口的增删改查或展示？                   → 普通 CRUD（Controller + Service）
```

3. **定形态**：每个 Model/Skill/Agent 再标 `ai` / `static` / `hybrid`；默认优先 static 或复用既有能力，避免为 AI 而 AI。
4. **定落点**：按下面映射写到需求卡「方案要点 → 归类落点」。
5. **文档先行**（必须先做）：
   - Model：更新 04 对应 Model 清单/契约；配置项写入后端配置文档。
   - Skill：更新 04 §3.1 Manifest 与内置 Skill 清单；被对话调用时更新 05 的 Tool 暴露说明。
   - Agent：更新 04 §3.3 与 05 的模式/编排/闸门说明。
   - 业务流程/CRUD：更新 02 模块清单、后端目录/权限文档、前端菜单说明。
   - 任何接口/表/权限/事件变化：同步对应端开发指南与需求卡。
6. **再给方案**：输出归类结论、文档变更清单、代码落点、风险与回滚。
7. **更新需求卡**：把归类结论与文档影响写回卡内。

## 归类落点速查

| 归类 | 后端落点 | 前端/客户端落点 | 权威文档 |
| :--- | :--- | :--- | :--- |
| Model（ai_model） | `module_ai` 模型配置与供应商工厂 | 模型配置页面 | 04 §2.2 |
| Model（static_func） | `module_ai/functions/` 注册表 | 无 | 04 §2.2 |
| Skill | `module_xxx/skills/<key>/manifest.py + impl.py` | 无（经 Agent/页面调用） | 04 §3.1 |
| Agent | `module_agent/agents/` 或模块内 Manifest | 对话页/任务页入口 | 04 §3.3 + 05 |
| 业务流程 | `module_xxx/service/ + dao/ + do/` | `src/modules/xxx/` | 02、后端开发指南 |
| 普通 CRUD | `module_xxx/controller/ + service/` | `src/modules/xxx/pages/` + `menu.ts` | 02、前端开发指南 |

## 输出模板

```markdown
归类结论：<Model | Skill | Agent | 业务流程 | 普通 CRUD>；形态：<ai | static | hybrid>

理由：<命中判定树哪一条；为什么不是相邻层>

文档先行（已完成/待完成）：
- [ ] <文档路径>：<改了什么>

代码落点：
- 后端：<目录/文件>
- 前端/客户端：<目录/文件>
- 迁移/配置：<无 或 具体项>

风险与回滚：<权限、兼容、性能、队列；如何回退>
```

## 禁止事项

- 跳过归类直接写代码。
- 把业务流程塞进 Skill，或把单次能力包成 Agent。
- 先改代码再补设计文档。
- 在需求卡里只写「用 AI 实现」，不写具体层与契约。
