# 05 - 开发 Skill（AI IDE 可执行的 Markdown prompt）

> 本目录是 **AI 开发流程的提示词资产**：纯 Markdown、无脚本依赖，可被 AI IDE 直接读取、拖入对话或自动发现。选中一个 Skill 后，在对话框补充本次任务细节即可。
> 规则来源：[README_AI.md](../../README_AI.md)（全局门禁）、[doc/README.md](../README.md)（文档治理）。**Skill 只写执行步骤，不复制全局硬规则。**

## 1. 使用方式

| 方式 | 操作 | 适用 |
| :--- | :--- | :--- |
| 拖入对话 | 把某个 `.md` 拖进 AI IDE 对话框，再补充任务细节 | 所有 AI IDE |
| 路径引用 | 在对话里写「按 `doc/05-开发skill/03-代码导入与文档回收.md` 执行」 | 支持文件读取的 IDE |
| 自动发现 | IDE 扫描 `doc/05-开发skill/*.md` 的 frontmatter，按 `triggers` 匹配 | 支持目录/规则扫描的 IDE |
| 组合使用 | 先 `01` 登记 → `02` 归类文档先行 → `05` 生成骨架 → `06` 交付 | 完整新功能 |

**推荐顺序**：`01 需求登记与批准` → `02 三层归类与文档先行` → `05 模块骨架生成` → `06 交付验收与发版`。外部代码先走 `03`，周期性走 `04`。

## 3. 文件格式（AI 可识别）

每个 Skill 文件必须以 YAML frontmatter 开头，字段固定：

```yaml
---
skill: <kebab-case-id>
name: <中文名>
version: 1
layer: project            # project | backend | frontend | flutter | deveops
triggers:                 # AI IDE 用于匹配；写用户会说的话
  - <触发词/场景>
inputs:                   # 执行前必须拿到的信息
  - <输入>
outputs:                  # 执行后的产物
  - <产物>
gate:                     # 必须满足的门禁
  - <门禁>
related:                  # 权威文档（只放链接，不复制内容）
  - <相对路径>
---
```

正文固定五段：**何时使用 → 执行步骤 → 输出模板 → 禁止事项 → 自检**。不要写教程、不要复制 `README_AI.md` 的硬规则、不要放单端实现细节。

## 4. 维护规则

- **规则单一来源**：全局规则改 [README_AI.md](../../README_AI.md)，文档归属改 [doc/README.md](../README.md)；本目录只同步「执行步骤」。
- **新增 Skill**：在本文件 §2 加一行 → 在 [doc/README.md](../README.md) §3 登记 → 在 [doc-manifest.yaml](../doc-manifest.yaml) 加 `layer: skill` 条目。
- **版本升级**：修改步骤或输出模板时 `version + 1`；破坏性变更在文件顶部写「迁移提示」。
- **后期脚本化**：保持 `skill` id、`triggers`、`inputs/outputs` 不变，把正文步骤替换为脚本调用即可；入口与用户使用方式不变。
- **不自动执行**：Skill 是提示词，不是自动化脚本；涉及写文件、改代码、跑命令时，仍受 AI IDE 的权限确认约束。
