# 模块骨架生成

## 何时使用

需求已批准、三层归类完成，需要新建后端 `module_xxx`、前端 `src/modules/xxx/` 或客户端 `lib/modules/xxx/` 时。

## 执行步骤

1. **确认归类**：先按 [02-三层归类与文档先行](02-三层归类与文档先行.md) 得出结论；纯 Skill/Agent 不一定要新模块。
2. **命名**：后端 `module_<域>`；前端/客户端 `<域>`；权限码 `域:资源:动作` 全小写。
3. **生成后端骨架**（垂直五件套 + 可选目录）：

```text
code/backend/server_py/src/module_xxx/
├── controller/        # 路由，仅参数校验 + 调 service
├── service/           # 业务逻辑唯一写业务处
├── dao/               # 数据访问
├── do/                # SQLModel 表模型 + Pydantic 请求/响应
├── dependencies/      # 分页/鉴权/重依赖惰性加载
├── config/            # permissions.py 权限声明 + server.py 模块初始化
├── tasks/             # 可选：异步任务
├── utils/             # 可选：非业务算法/工具
└── skills/            # 可选：<key>/manifest.py + impl.py（Skill 能力）
```

4. **后端接入**：
   - `src/app.py` 注册 controller import。
   - `config/permissions.py` 声明权限点。
   - 新表加 `table=True` 并生成 Alembic 增量脚本。
   - 动态配置加到 `common/config/dynamic/schemas.py`（可选）。
   - 异步任务在 `module_task/tasks/__init__.py` 注册（可选）。
5. **生成前端骨架**：

```text
code/frontend/vue3/src/modules/xxx/
├── api/          # 用 common/api/http.ts，不裸写 fetch
├── components/   # 模块内组件
├── pages/        # 页面，自动生成路由
└── types/        # 类型定义
```

   - `src/app/config/menu.ts` 加菜单项，`perm` 与后端权限点一致。
   - 首页入口加 `home: true`（如需要）。
6. **生成客户端骨架**（如需要）：

```text
code/frontend/flutter/lib/modules/xxx/
├── models/
├── services/
├── providers/
└── ui/
```

   - 在对话空态 `_EmptyView._features` 注册功能卡片。
   - 遵守四层单向依赖：`ui → providers → services → models`。
7. **文档登记**：
   - 02 模块清单加一行。
   - 后端目录/权限文档、前端菜单文档按需更新。
   - `doc/doc-manifest.yaml` 增加 `code → path` 映射。
   - 需求卡回写落点。
8. **验证**：

```bash
cd code/backend/server_py && python -c "import sys; sys.path.insert(0,'src'); import app"
cd code/frontend/vue3 && pnpm run build
cd code/frontend/flutter && flutter analyze
```

## 禁止事项

- 未归类就套模板。
- 在 controller 写业务逻辑，或跨模块挖对方 `service/` 内部文件。
- 只建目录不注册路由/菜单/权限。
- 新表不生成 Alembic 增量脚本。
- 新增模块不更新 02 模块清单与 manifest。
