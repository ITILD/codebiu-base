# 需求登记与批准

## 何时使用

用户提出新功能、功能变更或「想加一个东西」，且尚未在 [需求功能登记册](../02-设计文档/00-需求功能登记册.md) 登记时。

## 执行步骤

1. **判豁免**：缺陷修复、文档、纯重构、依赖升级不开卡；只在登记册「变更记录」加一行，然后结束。
2. **读上下文**：读 [需求与功能管理](../03-规范/需求与功能管理.md)、[需求卡模板](../02-设计文档/99-需求卡模板.md)、登记册最后 5 行，确认下一个 `REQ-<NNN>`。
3. **补关键信息**：只问缺失且影响方案的信息（给谁用、解决什么问题、必须满足的验收条件）。能从仓库推断的不要问。
4. **三层预判**：按 [04 §2.6](../02-设计文档/04-AI能力平台架构设计.md) 先给出 Model / Skill / Agent / 业务流程 / 普通 CRUD 的初步归类；不确定时在卡里写「待 02 Skill 确认」。
5. **填卡**：按模板写 `doc/02-设计文档/requirements/REQ-<NNN>-<短名>.md`，状态写「草案」。
6. **登记册加行**：在登记册表格追加 REQ 行与 FEAT 行，状态「草案」。
7. **请求批准**：输出「方案摘要 + 影响面 + 验收标准」，请用户回复「批准/同意/可以」。**不要替用户批准。**

## 输出模板

```markdown
已登记 REQ-<NNN>：<需求名>（草案）

- 三层预判：<Model | Skill | Agent | 业务流程 | 普通 CRUD>
- 影响面：新增 <...>；修改 <...>；数据 <...>；依赖 <...>
- 文档先行：需更新 <文档路径>（批准后执行）
- 验收标准：
  - [ ] <可操作条件>
  - [ ] 后端 import app 无报错；前端 pnpm run build 通过

回复「批准」后进入三层归类与文档先行；有修改意见直接说。
```

## 禁止事项

- 未登记就直接写功能代码。
- 替用户批准或把状态改成「已批准」。
- 需求卡只写一句话，缺少影响面与可勾选验收标准。
- 把豁免类改动伪装成需求卡。

## 自检

- [ ] 需求卡路径、编号、状态正确
- [ ] 登记册 REQ/FEAT 行与卡一致
- [ ] 三层预判已写
- [ ] 验收标准可逐条勾选
- [ ] 已明确请求批准，未越权推进
