# 代码导入与文档回收

## 何时使用

外部传入代码、从别的项目拷贝模块、用户手工改了代码但没有同步文档，或合并一个来源不明的补丁时。

**原则：先映射，后合入；无法映射到文档的代码不得进入公共底座。**

## 执行步骤

### 1. 盘点

```bash
git status --short
git diff --stat
git ls-files --others --exclude-standard
```

外部目录先对比出「新增 / 修改 / 删除」三张清单；记录来源（谁提供、哪个仓库/分支、是否含手工改动）。

### 2. 分端与分层

按路径判断归属端：`code/backend/`、`code/frontend/vue3/`、`code/frontend/flutter/`、`deveops/`。
再按 [04 §2.6](../02-设计文档/04-AI能力平台架构设计.md) 判断每个改动属于 Model / Skill / Agent / 业务流程 / CRUD / 工程配置。

### 3. 找归属文档

查 [`doc/doc-manifest.yaml`](../doc-manifest.yaml) 的 `code` 映射：

- 命中：记录 `code → path`，进入第 4 步。
- 未命中：先补 manifest 条目，再继续；**不允许「无主代码」**。

### 4. 契约比对

逐项检查代码事实与文档是否一致：

| 检查项 | 看什么 | 不一致时 |
| :--- | :--- | :--- |
| 接口 | 路径、方法、请求/响应、错误码、SSE 事件 | 以设计意图为准修正代码，或更新契约并说明原因 |
| 数据 | 表、字段、索引、迁移脚本 | 补 Alembic 脚本与数据模型文档 |
| 权限 | `域:资源:动作`、前端 `menu.ts` | 前后端同时修正，写进权限文档 |
| 配置 | `config.yaml` / 动态配置 schema / 环境变量 | 更新配置文档与运维手册 |
| 三层 | Skill Manifest、Agent 定义、Tool 暴露 | 更新 04/05 与需求卡 |
| 队列/部署 | 队列名、worker、定时任务 | 更新运维文档 |

### 5. 决定去留

- **接受**：符合基线分层与规范 → 回写文档后合入。
- **改造**：能复用但落点不对 → 移到正确层/目录，再回写。
- **拒绝**：触碰公共底座且无兼容说明、引入 500MB+ 大库、无法映射 → 退回提供方，不直接合入。

### 6. 回写文档

按顺序更新：

1. 需求卡：来源、影响面、三层归类、验收标准。
2. 设计/契约：04/05、02、各端开发指南。
3. `doc/doc-manifest.yaml`：新增/修正 `code → path` 与 `sync_triggers`。
4. 根展示页：能力或定位变化时同步 `README.md` 与 `README.en.md`。
5. 登记册「变更记录」：加一行，注明「外部/手工代码回收」。

### 7. 验证

```bash
# 后端
cd code/backend/server_py && python -c "import sys; sys.path.insert(0,'src'); import app"
# 前端
cd code/frontend/vue3 && pnpm run build
# 文档
# 按 04-文档代码同步巡检.md 检查链接、双语、清单
```

## 禁止事项

- 先把代码合入，再补文档。
- 对「外部代码」例外放行，不检查权限/迁移/依赖。
- 只改代码不改 `doc-manifest.yaml`。
- 删除或重命名文档后不修正引用。
