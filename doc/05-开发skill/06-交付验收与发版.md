# 交付验收与发版

## 何时使用

功能开发完成、准备交付或发版时；或用户说「收口」「验收」「发版」。

## 执行步骤

### 1. 逐条验收

打开需求卡「4. 验收标准」，逐条执行并勾选。不能把「代码写完了」当验收通过。

```bash
# 后端
cd code/backend/server_py
python -c "import sys; sys.path.insert(0,'src'); import app"
uv run pytest tests -x          # 如项目有对应测试
# 前端
cd code/frontend/vue3
pnpm run build
# 客户端（如涉及）
cd code/frontend/flutter
flutter analyze
```

### 2. 文档同步检查

- [ ] `@doc-sync` 指向的文档已更新
- [ ] `doc/doc-manifest.yaml` 映射已更新
- [ ] 02/04/05 等设计文档与实现一致
- [ ] 根展示页改动已同步 `README.md` 与 `README.en.md`
- [ ] 新增文档已在 [doc/README.md](../README.md) 与 manifest 登记

### 3. 需求状态收口

- 需求卡：勾完验收标准 → 状态「已交付」→ 第 5 节补交付记录（日期、版本、验收结论）。
- 登记册：REQ/FEAT 行状态改「已交付」。
- 如涉及外部/手工代码：确认已按 [03-代码导入与文档回收](03-代码导入与文档回收.md) 留痕。

### 4. 版本与变更记录

按 [版本管理](../03-规范/版本管理.md) 更新：

- 后端 `pyproject.toml` / 前端 `package.json` / 客户端版本号（按实际发版范围）。
- 前端 `versions.ts`（如项目使用）。
- 各端 `doc/tag_doc/version_info.md` 追加变更记录。
- 登记册「变更记录」追加一行。

### 5. 交付说明

输出给用户的说明只保留：做了什么、验收结果、升级/迁移注意、回滚方式。

## 输出模板

```markdown
交付：REQ-<NNN> <需求名>
版本：<版本号 / 未发版>

验收：
- [x] <验收标准 1>
- [x] <验收标准 2>
- [x] 后端 import 无报错
- [x] 前端 build 通过

文档同步：<已完成项；未完成项与原因>
迁移/升级：<Alembic 脚本、配置变更、兼容说明 / 无>
回滚：<方式>

状态：登记册与需求卡已置「已交付」
```

## 禁止事项

- 验收标准未全勾就置「已交付」。
- 只改登记册不改需求卡（或反之）。
- 发版不写版本记录与迁移说明。
- 文档未同步就宣布交付。
