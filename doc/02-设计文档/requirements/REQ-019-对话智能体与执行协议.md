## 3. 方案要点

- 表：`ai_agent.chat_modes`（JSON：思考档位 / 检索轮次 / 四重预算）、`agent_plan_item`（清单投影）、`agent_plan_event`（事件日志）、`skill_invocation`（+ `agent_run_id`）
- 接口：
  - `POST /rag/chat`（既有扩展：`mode`=auto/fast/thinking、`agent_id`；响应含 `exec_mode`、`mode_reason`）——登录
  - `GET /agent/agents` / `GET /agent/agents/{id}/modes`（内置对话 Agent 与模式预算视图）——登录
  - `GET /agent/plans/{run_id}` / `GET /agent/plans/{run_id}/events`（清单投影与事件回放）——登录（本人或管理员）
- 页面：vue3 `modules/agent` 智能体页新增「内置对话 Agent」只读区；`modules/chat` 会话输入区加模式选择器 + 思考过程折叠区；flutter 聊天页同步模式选择器，**不新增页面层级**
- 复用：既有 LangGraph 编排图 + PostgreSQL checkpointer、SkillRuntime、Celery 双队列、权限与动态配置、既有 AG-UI 事件扩展点
- 关键约束（不变量）：禁止 Agent 调 Agent；Skill 不互相编排；完成判定只能由验收给出，模型无「完成」按钮；AI 不得访问用户无权限的知识库；预算耗尽必须优雅降级

## 4. 验收标准

### 批次 4

- [ ] `mode=auto|fast|thinking` 三档请求均返回 `exec_mode` 与 `mode_reason`，前端可见决策理由
- [ ] 用户显式 `fast` 不被自动升级为 deep；`auto` 在复合问题上自动升级到 deep
- [ ] 无知识库 / 未开联网 / 沙箱未就绪时，对应工具不出现在 tool-calling 清单
- [ ] 深度模式在墙钟 90s 或工具 12 次触顶时优雅收尾，返回已收集证据与 `stop_reason`
- [ ] 规划步骤 `think_level=high`、工具结果回填步骤 `think_level=off`，可从事件流核对
- [ ] 同一 Skill 在一次会话内连续失败 2 次后被摘除，并下发 `skill_masked` 事件
- [ ] `sys.container_*` 调用写 `skill_invocation`；`ops_agent` 运行写 `agent_job_run`
- [ ] 探针进程仍可独立部署，Bearer 鉴权与服务名过滤生效

### 批次 5

- [ ] 清单由模型 `write_plan` 创建、运行时校验 schema，落 `agent_plan_item`
- [ ] 验收失败两次触发强制改单，改单超过 3 次以 `replan_budget` 收尾
- [ ] `acceptance_hash` 变化时 verifier 拒绝「改验收过闸」
- [ ] judge 验收上下文不含执行者思维链与自述
- [ ] 单轮上下文投影稳定在 1.5k token 预算内，且验收标准永不截断
- [ ] 假完成率、成功任务成本、任务成功率三项指标可从 `agent_plan_item` + `skill_invocation` 统计

### 通用

- [ ] 后端 `import app` 无报错；前端 `pnpm run build` 通过
- [ ] 既有问答、上传、检索回归通过（模式改造不破坏原链路）
