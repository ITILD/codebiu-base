# 01 - 需求分析
> 范围：`code/backend/server_py`（FastAPI 后端 base-server）与 `code/frontend/vue3`（Vue3 前端 CODE_BIU）；技术实现见 [02-总体架构与功能设计](./02-总体架构与功能设计.md)，权限见 [03-权限设计](./03-权限设计.md)。
> **基线定位**：精简基线保留认证授权、系统管理、统一文件、AI 基础能力、RAG、文档解析、任务队列；智能体、邮件、个人小站、生活工具、地理空间、网页搜索等业务模块已裁剪，可按基线模块范式扩展。

## 1. 项目概述
CodeBiu 是 AI 能力驱动的模块化全栈业务平台：后端 Python 3.13 + FastAPI（8 个 module_* + common，可独立挂载/裁剪），前端 Vue 3 + Vite（模块化页面与后端一一对应，自动路由 + 权限过滤）。核心 AI 场景为知识库（RAG）问答，另内建系统管理、统一文件存储、异步任务队列（本地 + Celery 双引擎），可整体作底座或裁剪为单一产品。

### 1.1 核心价值
| 价值点 | 说明 |
|--------|------|
| AI 全家桶 | 模型配置管理 + 多供应商 LLM 接入 + SSE 流式对话 + RAG 问答 + 重排 + 语音（ASR/TTS）+ OCR |
| 开箱即用的权限底座 | Casbin 域隔离 RBAC + 项目级成员档位，模块自治声明权限 |
| 多存储统一抽象 | 关系库（PostgreSQL/SQLite）、缓存（Redis/Fakeredis）、向量库（Milvus 远程 / LanceDB 本地，依赖按需安装）可配置切换 |
| 文件服务内容寻址 | SHA-256 去重秒传、分片断点续传、local/S3 无缝切换 |
| 异步任务中心 | 本地/Celery 双引擎任务创建/轮询/取消/重试，task_queue 表为状态事实来源 |

## 2. 用户角色与画像
| 角色 | 来源 | 典型诉求 |
|------|------|----------|
| 游客 | 未登录 | 访问首页了解平台；点击受保护入口时被引导登录/注册 |
| 普通用户 | 注册后自动获得 | 与 AI 对话、创建个人知识库并上传文档问答、使用文件管理等日常功能 |
| 知识库协作者 | 被邀请进项目 | 按档位（只读/编辑/管理）参与他人知识库的协作 |
| 系统管理员 | 首个注册用户自动授予 | 管理用户/角色/部门/权限/策略规则，为角色分配模块权限，管理模型配置与任务队列 |

## 3. 功能需求
按业务域组织，编号与后端模块对应（基线裁剪后部分不连续），每条注明承载端（后端 / 前端）。

### FR-1 认证与账户（module_authorization / authorization 模块）
- 用户名 + 密码注册、登录、登出；注册/登录返回双令牌 + 用户信息，access_token 由 refresh_token 自动续期，登出后令牌即时失效。
- 自助维护昵称/邮箱/电话/头像，改密校验旧密码；管理员可禁用账户（is_active），禁用后登录与刷新均被拒绝。

### FR-2 系统管理（module_authorization + module_main / admin 后台）
- **组织与权限**：用户 CRUD（分页/启停/重置密码/头像）、角色 CRUD 与角色-权限分配、部门树、权限（菜单）树查询、Casbin 策略规则管理。
- **字典**：类型/项 CRUD，无限滚动加载与按编码查询，供业务下拉选项。
- **监控与运维工具**：服务器状态（缓存 60s）、系统信息、硬件、网络、挂载子应用列表；开发用数据表/向量库/缓存清单查看与重置数据库。
- **通用配置**：token/email/sms/file_system/db_cache/db_vector/tasks 等动态配置组在线读写（首启种子入库，页面即表单）。

### FR-3 知识库（module_rag / rag 模块）——核心需求
- **项目管理**：知识库项目增删改，支持分类（个人/项目/公司）与私有/公开标记；每项目惰性创建虚拟目录 `/rag/<项目名>/`。
- **文档入库**：上传（与统一文件服务打通，支持直传/中转/分片/秒传）→ module_office 解析（MinerU 外部服务，工厂接口可扩展）→ 智能切分（通用/表格策略，可由 LLM 推荐）→ 向量化入库；解析异步（Celery），支持进度追踪、失败重试、重新解析、重新向量化；分块可查看、可管理。
- **检索**：稠密向量（语义）+ 稀疏向量（BM25 关键词）混合检索，RRF 融合重排，可选 Rerank 精排与分数阈值过滤。
- **知识库问答（RAG Chat）**：多轮对话，关联一个或多个知识库；LangGraph 流程：意图分析（提取检索关键词、判断是否需要知识库）→ 知识库检索 → LLM 生成；SSE 流式（统一 AG-UI 协议事件流），区分推理/意图分析/知识检索/正式回答区块；会话列表与消息持久化、历史分页；"深度思考"（Rerank 精排）开关；自动生成会话标题与历史压缩总结。
- **成员协作**：按用户/按部门邀请，三档角色（reader/editor/admin）；部门授权沿部门树级联生效；公开项目对登录用户只读。
- **个人模型配置**：用户可绑定自己的对话/向量/重排模型（支持共享标记），问答按用户加载。

### FR-5 AI 服务（module_ai / ai 模块）
- **模型配置管理**：CRUD（server_type：openai/dashscope/vllm/ollama/aws-bedrock 等，自动补默认地址），用户私有配置 + 共享标记。
- **通用 LLM 对话**：SSE 流式端点（legacy/AG-UI 双协议），历史经 localStorage 本地保存；**重排**：Rerank 精排端点，供 RAG 深度思考等场景调用。
- **语音与 OCR**：ASR 文件识别、ASR 流式（WebSocket）、TTS 文件（WAV）、TTS 流式（PCM 边收边播），纯在线服务（dashscope/openai 协议分派），无本地引擎；OCR 用百炼 qwen-vl-ocr，整图识别无坐标框，语言自动检测。

### FR-7 文件管理（module_file / file 模块）
- 虚拟文件树（目录/文件条目）：新建目录、重命名、移动（同步维护子树路径）、批量删除（软删 + 引用计数归零清理物理文件）。
- 上传四件套：小文件直传（SHA-256 去重秒传）、S3 预签名直传、服务端中转、分片（init/parts/complete/取消）；下载 S3 走 302 直链、本地流式返回；存储后端 local/S3 配置驱动切换，支持迁移。

### FR-11 任务队列（module_task / task 模块）
- 统一异步任务入口（本地/Celery 双引擎，config `tasks.engine` 切换，共用 task_queue 表与查询接口）：创建/投递、列表/详情/统计、进度轮询、取消、重试、与 Celery 结果后端对账（local 跳过）；任务类型注册表供前端下拉；RAG 文档解析与全库重向量化经此投递；worker 启动自愈（长期 PENDING 按当前引擎重派发）。

### FR-14 脚手架模板（module_template / 后台模板页）
- 标准 CRUD 示例、文件上传/流式返回扩展示例、async/sync 并发行为教学端点。

### FR-15 前端平台能力
- 首页应用入口卡（按权限过滤）；后台工作台（状态卡 + 快捷入口 + 最近访问）；全局登录/注册弹窗、账户设置页（资料/改密/外观/我的权限）。
- 后台侧边栏菜单（权限过滤）、面包屑、暗色主题（三态）、中/日/英基础国际化；消息渲染 Markdown + LaTeX + Mermaid + 表格 + 过程区块折叠，复制/导出 Word/PDF；统一存储上传流程（哈希 → 直传/中转/秒传适配器）。

## 4. 非功能需求
| 类别 | 编号 | 需求 |
|------|------|------|
| 安全 | NFR-1 | 密码 argon2 哈希存储；JWT 双令牌；登出即吊销（Redis 黑名单 + refresh 落库置位） |
| 安全 | NFR-2 | 全接口 RBAC 鉴权（Casbin），未声明动作从严拒绝（fail-closed） |
| 安全 | NFR-3 | 个人数据按 user_id 隔离；项目内资源按成员档位校验 |
| 性能 | NFR-4 | AI 长对话 SSE 流式输出，检测客户端断连主动终止生成；LLM 请求超时 300s |
| 性能 | NFR-5 | 文档解析/向量化异步化（本地/Celery 双引擎），不阻塞接口；任务进度实时回写 task_queue（Celery 引擎另写 update_state） |
| 性能 | NFR-6 | 服务器状态接口 60s 缓存；系统状态响应带 X-Process-Time 耗时头；GZIP 压缩 |
| 可扩展 | NFR-7 | 后端模块自治（controller/service/dao/do/config/dependencies 分层），app.py 一行挂载；权限由模块声明、注册中心幂等同步 |
| 可扩展 | NFR-8 | 三类数据库（关系/缓存/向量）与文件存储均可通过配置切换实现 |
| 可移植 | NFR-9 | 开发态支持 SQLite + Fakeredis 零外部依赖运行（向量库依赖按需安装：milvus/lancedb）；生产可切换 PostgreSQL + Redis |
| 兼容 | NFR-10 | 前端支持桌面与移动端响应式（isMd/isLg 断点）；暗色模式 |
| 可维护 | NFR-11 | 统一日志体系（控制台 + 文件按日轮转）；统一异常处理（BizError/ValueError→400/兜底→500）；OpenAPI 文档 `/docs` |
| 测试 | NFR-12 | 后端 pytest（asyncio 自动模式）；前端 Playwright 三浏览器 E2E |

## 5. 运行环境需求

### 5.1 后端依赖
| 组件 | 开发默认 | 可切换（生产） | 用途 |
|------|----------|----------------|------|
| Python | ≥ 3.13（uv 管理） | — | 运行时 |
| 关系数据库 | PostgreSQL（或 SQLite） | SQLite/PostgreSQL | 业务表、Casbin 策略、LangGraph checkpointer |
| 缓存 | Fakeredis（本地持久化） | Redis | token 黑名单、Celery broker/backend |
| 向量库 | Milvus（远程，主用）/ LanceDB（本地备选） | pymilvus / lancedb(按需) | 知识库分块向量（纯稠密向量检索，score=1/(1+distance)） |
| 对象存储 | S3（localhost:9000） | 任意 S3 协议/本地磁盘 | 统一文件存储 |
| AI 模型 | 按用户 model_config 配置 | OpenAI 兼容端点/Ollama/AWS Bedrock 等 | LLM/Embedding/Rerank/ASR/TTS |

### 5.2 前端依赖与端口
- Node ≥ 22（pnpm 管理），Vite 开发服务器默认代理 `/base_server` → 后端 `http://127.0.0.1:6666`。

| 服务 | 端口 |
|------|------|
| 后端 API（uvicorn） | 6666（config.yaml `server.port`） |
| 前端开发服务器 | 8888（VITE_PORT） |
| 对象存储（S3） | 9000 |
