# 配置与数据库初始化（部署）
> 面向**首次部署 / 新环境上线**：配置准备、建库、首启行为、验证与重置。
> 配置加载与启动时序的代码级说明见 [server_py 03-配置与初始化](../../code/backend/server_py/doc/dev/03-配置与初始化.md)。

## 1. 首启行为
**不会自动执行 Alembic 升级**，仅做：

1. 连接 `db_rel`（关系库）；
2. 创建 `sys_config` 并把 `config.yaml` 业务组种子入库；
3. 创建缺失的关系库表（`create_all`，只建缺失表）；
4. 全新库自动 `alembic stamp head`；
5. 初始化 Casbin 策略、默认管理员、基础字典、审计等幂等钩子；
6. 按需创建 S3 桶、启动任务调度。

## 2. 配置准备

### 2.1 配置层级
| 层级 | 文件/来源 | 是否入 git | 说明 |
| :--- | :--- | :--- | :--- |
| 基线 | `config.yaml` | 是 | 零依赖默认值、引导配置、密钥占位 |
| 覆盖 | `config.dev.yaml`（或任意 `config.prod.yaml`） | 否 | 真实库地址、模型密钥、管理员密码 |
| 环境变量 | `CODEBIU_*` | — | 最高优先级，容器/K8s 推荐 |

`config.yaml` 的 `config.local_file` 决定加载哪份覆盖文件；**指定的文件不存在会直接报错**。

### 2.2 最小配置清单
```yaml
# config.yaml（基线，按部署环境修改）
config:
  local_file: config.prod.yaml

server:
  host: 0.0.0.0
  port: 6666                 # 对外端口按 nginx/容器映射调整

dir:
  base: temp_source          # 运行期文件根目录（需持久化）

db_rel:                      # 引导配置，始终以 yaml 为准
  type: postgres
  host: postgres              # compose 网络内用服务名
  port: 5432
  user: codebiu
  password: ""               # 真实密码放覆盖层/环境变量
  database: codebiu
```

```yaml
# config.prod.yaml（覆盖层，gitignored）
db_rel:
  host: postgres
  port: 5432
  user: codebiu
  password: <强密码>
  database: codebiu

token:
  secret_key: <至少 32 位随机串>

mineru:
  token: <真实 token>
```

```bash
export CODEBIU_DB_REL__HOST=postgres
export CODEBIU_DB_REL__PASSWORD='<强密码>'
export CODEBIU_TOKEN__SECRET_KEY='<随机串>'
```

> **禁止**把真实密码/Token 写进 `config.yaml`；基线只保留 `to set real key` 占位。
> 修改 `token.secret_key` 会使所有已登录会话失效。

### 2.3 业务动态配置
`db_cache`、`db_vector`、`file_system`、`token`、`login_security`、`email`、`sms`、`tasks`、`websearch`、`parser`、`audit`、`admin` 等组：

- **首启以 yaml 同名节为种子入库**，之后以「系统管理 → 通用配置」页为唯一事实来源；再次修改 yaml 不覆盖已入库值（`db_rel/server/dir/mineru` 等引导配置除外）；
- 首次部署前把长期使用的业务配置写好，或首启后立即在配置页确认。

> `default_models` 不是动态配置组：它是「模型配置」表的启动补种开关，`reset_models=false`（基线默认）时完全不碰库中模型。

## 3. 数据库初始化

### 3.1 PostgreSQL
应用**只建表不建库**，必须先创建空库：

```bash
# 容器内
docker exec -it <pg容器> psql -U codebiu -c "CREATE DATABASE codebiu;"

# 或宿主机
psql -h <host> -p <port> -U codebiu -c "CREATE DATABASE codebiu;"
```

可选扩展（按需，需 DBA 权限）：

```sql
CREATE EXTENSION IF NOT EXISTS vector;      -- pgvector（如使用）
CREATE EXTENSION IF NOT EXISTS postgis;     -- 空间数据（如使用）
```

### 3.2 SQLite（开发/单机）
无需建库，路径由 `db_rel.database` 指定（默认在 `dir.base_child.db` 下），首次启动自动创建文件。生产不建议使用 SQLite。

> Linux 部署请把基线里 Windows 风格路径（`temp_source\db\data.db`）改为 `temp_source/db/data.db`，或在覆盖层重写。

### 3.3 缓存 / 向量库
| 组件 | 初始化方式 |
| :--- | :--- |
| Redis | 启动 Redis 服务；在通用配置页或 yaml 填连接信息 |
| Fakeredis | 零依赖默认，本地文件持久化 |
| Milvus | 启动 Milvus 服务；集合由应用按需创建 |
| LanceDB | 零依赖本地文件，路径在 `dir.base_child.db` |

向量库结构**不在 Alembic 管理范围**；换向量库类型需重建向量索引（见第 6 节）。

### 3.4 对象存储
`file_system.storage_type=s3` 时，应用启动会自动创建桶（runtime 钩子）；需提前准备：

- endpoint、access_key、secret_key、bucket、region；
- bucket 名需符合 S3 规范（小写字母/数字/连字符/点，无下划线）。

无对象存储时改为 `storage_type: local`，接口不变。

## 4. 启动与验证
```bash
# 1. 启动后端（在 server_py 目录）
cd code/backend/server_py
python src/app.py

# 2. 健康检查
curl -s http://127.0.0.1:6666/docs >/dev/null && echo OK

# 3. 前端（开发）
cd code/frontend/vue3 && pnpm run dev

# 4. 生产：nginx 托管 dist + 反代 /base_server
```

验证清单：

- [ ] 后端启动日志无 `server_start error`、无配置缺失报错
- [ ] `/docs` 可访问
- [ ] 默认管理员可登录（`admin / admin123`，首启后立即修改）
- [ ] 「系统管理 → 通用配置」能看到动态配置分组
- [ ] 文件上传/下载可用（local 或 S3）
- [ ] AI 模型测试可用（如已配置）
- [ ] 数据库 `alembic_version` 存在且为 `head`

```bash
cd code/backend/server_py
uv run alembic current
```

## 5. 首启模式：`state.check_db`
| 值 | 行为 | 适用 |
| :--- | :--- | :--- |
| `true`（默认） | 建缺失表 + 全新库 stamp + 初始化钩子 | 开发、全新部署 |
| `false` | 跳过建表/stamp/初始化钩子 | 生产（结构已由 Alembic 准备好） |

生产：首次上线可用 `true` 完成建表与种子；升级前执行 `alembic upgrade head` 再以 `false` 启动；**不要**多实例同时以 `true` 启动做初始化。

## 6. 重置与重建
| 场景 | 操作 |
| :--- | :--- |
| 忘记管理员密码 | 在「系统管理 → 通用配置 → 管理员」开启 `reset_password` → 重启一次 → 关闭并改密；无法登录时直接改 `sys_config` 的 admin 分组 |
| 重建 PostgreSQL | 停服务 → 备份 → `DROP/CREATE DATABASE` → `state.check_db=true` 启动 |
| 重建 SQLite | 停服务 → 删除 `data.db`（含 WAL/SHM）→ 重启 |
| 重置动态配置 | 停服务 → 清理 `sys_config` 对应分组 → 重启重新种子；或配置页改回 |
| 更换向量库 | 停服务 → 配置新库 → 重建向量索引（重新向量化知识库文档） |
| 更换对象存储 | 先 `sync` 同步双副本，再切 `storage_type`，验证后清理旧存储 |

## 7. 上线后的配置收尾
首启只保证系统能跑；以下业务配置需在「系统管理 → 通用配置」逐组确认（保存即生效，多进程最多约 10 秒同步）：

| 配置组 | 必填项 | 说明 |
| :--- | :--- | :--- |
| `admin` | 管理员密码 | 立即改掉默认 `admin123` |
| `login_security` | 失败锁定次数/时长、密码强度、二次验证 | 按等保/业务要求调整 |
| `token` | 访问/刷新令牌有效期、密钥 | 密钥变更会使已登录会话失效 |
| `file_system` | `storage_type`、单文件上限、S3 参数 | 先确认上传下载可用 |
| `default_models`（模型种子） | 对话/向量化/重排/OCR/语音模型 | 在「模型配置」页测试通过后再启用；只有 `reset_models=true` 才按 yaml 补种 |
| `email` / `sms` | SMTP / 短信服务参数 | 验证码、通知依赖 |
| `websearch` | 搜索服务与配额 | RAG 联网功能依赖 |
| `parser` | 解析引擎路由顺序 | 具体 OCR 厂商在「模型配置」中维护 |
| `tasks` | `engine=local/celery`、并发数 | 切换引擎需重启 |
| `mineru`（引导配置） | 服务地址、token | 文档解析依赖，改 yaml 后重启 |
| `db_vector` | 向量库类型/连接 | 换库后需重建索引 |

验证顺序：登录 → 用户/角色/菜单 → 文件上传下载 → 模型测试 → 知识库解析/问答 → 通知/任务。

## 8. 常见问题
| 现象 | 处理 |
| :--- | :--- |
| `config.local_file 指定的配置文件不存在` | 创建覆盖文件，或把 `config.local_file` 置空 |
| 连不上 PostgreSQL | 容器网络用服务名；库是否创建；端口/密码；`psql` 先验证 |
| 表没建出来 | `state.check_db=false`；改回 `true` 或先执行 Alembic |
| 改了 yaml 不生效 | 业务组已入库，改通用配置页；引导配置才始终读 yaml |
| 管理员密码不对 | 在「通用配置 → 管理员」开启 `reset_password`；确认连的是目标库 |
| 上传 413 | nginx `client_max_body_size` 与 `file_system.max_size` 同时调大 |
| AI 对话不流式 | nginx 反代关闭 `proxy_buffering` |
