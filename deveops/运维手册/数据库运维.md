# 数据库运维
PostgreSQL 日常备份、恢复、结构迁移。首次部署见 [配置与数据库初始化](配置与数据库初始化.md)；跨版本升级见 [版本升级与数据库迁移](版本升级与数据库迁移.md)。

## 1. 部署形态
- 容器：`postgres:17`（需要 PostGIS/pgvector 时换 `postgis/postgis:17-3.5`；pgvector 按需启用）
- 宿主机端口：`15432` → 容器 `5432`
- 数据目录：`postgres/data`(相对部署目录 `deveops/运维脚本/docker_dev/compose`，务必持久化)

## 2. 备份

### 逻辑备份(推荐日常使用)
```bash
# 全库导出(压缩自定义格式)
docker exec -t <db容器名> pg_dump -U codebiu -Fc codebiu \
  > backup_$(date +%Y%m%d).dump

# 仅结构 / 仅数据
docker exec -t <db容器名> pg_dump -U codebiu -s codebiu > schema.sql   # 结构
docker exec -t <db容器名> pg_dump -U codebiu -a codebiu > data.sql    # 数据
```

### 定时备份(crontab 示例)
```bash
# 每日 2:00 备份,保留 14 天
0 2 * * * docker exec -t <db容器名> pg_dump -U codebiu -Fc codebiu | gzip > /backup/db_$(date +\%Y\%m\%d).dump.gz && find /backup -mtime +14 -delete
```

### 物理备份(冷备)
```bash
# 停库后打包数据目录(必须先停库;命令在部署目录执行)
bash ctl.sh down
tar czf pgdata_$(date +%Y%m%d).tar.gz postgres/data
bash ctl.sh up
```

## 3. 恢复
```bash
# 自定义格式恢复
docker exec -i <db容器名> pg_restore -U codebiu -d codebiu \
  --clean --if-exists < backup_20260101.dump

# SQL 文本恢复
docker exec -i <db容器名> psql -U codebiu -d codebiu < schema.sql
```

## 4. 结构迁移(Alembic)
> 基线表结构演进统一走 Alembic，迁移脚本位于 `code/backend/server_py/alembic/versions/`（**随 git 提交**）。

### 机制
- **全新库**：主服务首启 `create_all` 建全量表后自动 `alembic stamp head`(写 `alembic_version` 表)，无需人工干预
- **结构变更**：改 DO 模型后生成迁移脚本，部署时升级；**启动只打标不升级**（多 worker 避免竞争，升级由运维显式执行）

### 常用命令(均在 `code/backend/server_py` 目录执行)
```bash
cd code/backend/server_py
uv run alembic current                                    # 当前版本
uv run alembic history                                    # 迁移链
uv run alembic revision --autogenerate -m "dict加字段"     # 生成迁移(需人工检查后提交)
uv run alembic upgrade head                               # 升级到最新
uv run alembic downgrade -1                               # 回滚一步
uv run alembic stamp head                                 # 存量库一次性接入
```

### 发布升级流程
1. 备份(见第 2 节)
2. `alembic upgrade head`
3. 重启后端(`state.check_db=false` 的部署**必须先升级再启动**)

### 存量库首次接入(表已由 create_all 建好、无版本表)
```bash
alembic stamp head   # 打上基线标记, 之后随版本正常 upgrade
```

### 注意事项
- 连接与主服务**同源**：读 `common/config/index.py` 的 `db_rel` 节(config.yaml + config.dev.yaml + `CODEBIU_*` 环境变量)，换库改同一份配置
- 向量表(Milvus)不纳入 Alembic，仍由向量后端自建

## 5. 迁移到新服务器
```bash
# 旧机导出(见上节备份)
# 新机:
#   ① 启动空库容器(初始化脚本可放 postgres/init/)
#   ② 执行恢复
#   ③ 更新后端 config.yaml 的 db_rel.host 并重启 server_py
```

## 6. 向量扩展(RAG 场景)
知识库向量检索依赖 pgvector：

```sql
-- 连接库后执行(有 DBA 权限时)
CREATE EXTENSION IF NOT EXISTS vector;

-- 验证
SELECT extname FROM pg_extension;
```

> 向量库读写已封装于后端 `common/utils/db/`，扩展安装失败会在启动日志中体现。

## 7. 日常检查清单
| 项 | 命令/方式 | 频率 |
| :--- | :--- | :--- |
| 容器存活 | `docker compose ps` | 每日 |
| 磁盘水位 | `df -h`(data 目录所在盘 >80% 告警) | 每日 |
| 备份产物 | 检查 `/backup` 最新文件时间 | 每日 |
| 迁移版本 | `alembic current`(部署机) | 每次发布 |
| 慢查询 | `pg_stat_statements`(如启用) | 每周 |
| 连接数 | `SELECT count(*) FROM pg_stat_activity;` | 每周 |
