# 任务与调度运维

> 范围：异步任务队列（local/celery 双引擎 worker）与周期调度（定时任务）的部署、切换与日常管理。
> 关联需求：REQ-012（定时任务）、REQ-010（测试基线）。

## 1. 双引擎总览

| 引擎 | 配置 `tasks.engine` | 组成 | 适用 |
| :--- | :--- | :--- | :--- |
| local | `local`（默认） | API 进程内 asyncio 后台协程（执行）+ 调度循环（触发） | 单机/开发/小规模，零额外组件 |
| celery | `celery` | API 进程（投递）+ worker 进程（执行）+ beat 进程（触发，可选） | 生产/横向扩容，需 Redis |

切换入口：`config.yaml` 的 `tasks` 段，或运行时在 **系统配置 → 任务队列** 修改（`engine` 对新建任务即时生效；broker 地址变更需重启 worker）。

## 2. 进程启动

```bash
cd code/backend/server_py

# API 服务(两种引擎都需要)
python src/app.py

# ---- 仅 celery 引擎需要 ----
celery -A src.app_task worker   # 任务执行进程(可多实例; Windows 建议 --pool=solo)
celery -A src.app_task beat     # 周期调度触发进程(需要定时任务时启动, 全局单实例)
```

- local 引擎：无需 worker/beat，API 进程内完成执行与调度（Web 进程不加载 celery 库，零额外内存）。
- celery 引擎：worker 消费 `task_queue` 队列；beat 每分钟 tick 一次扫描到期调度。

## 3. 定时任务（周期调度）

### 3.1 使用入口

后台 **任务队列 → 定时任务** 页面（权限码 `task:schedule:*`），或接口 `/task/schedules`。

- 触发方式二选一：5 字段 cron 表达式（`分 时 日 月 周`，分钟级精度）或固定间隔（秒，≥60）
- 调度定义落库（`task_schedule` 表）：新增/启停/改周期**即时热生效**（local 引擎立即唤醒调度循环；celery 引擎下一分钟 tick 生效），无需重启
- 每次触发生成一条 `task_queue` 记录（执行历史在 任务列表 页按类型筛选），调度行回写"最近执行"快照
- 停机错过的触发**不补跑**（恢复时从当前时刻重算），避免历史窗口雪崩

### 3.2 内置示例

首次启动自动播种 **审计日志周期清理**（任务类型 `sys_audit_purge`，每日 04:00，**默认停用**）：
在定时任务页启用即可按 **系统配置 → 操作审计** 的保留期（`audit.retention_days`）周期清理过期审计记录。

### 3.3 调度开关

动态配置 `tasks.scheduler_enabled`（系统配置 → 任务队列）：
- local 引擎：控制是否启动进程内调度循环
- celery 引擎：控制 beat tick 是否派发（beat 进程启动时读取，修改后需重启 beat）

## 4. 内存与体积设计（运维须知）

- **零新增依赖**：cron 解析为自研 5 字段解析器（`module_task/utils/cron.py`），不引入 croniter/APScheduler
- **local 调度循环单协程**：无常驻调度缓存，每轮仅一次到期索引查询（单轮限 20 条），休眠截断 `[1s, 30s]`；旁路改库最迟 30s 被感知
- **执行历史不建关联表**：调度行只存最近一次执行快照（`last_task_id/last_status`），防表膨胀；完整历史即 `task_queue` 本身（可配审计清理类任务周期瘦身）
- **local 引擎 Web 进程不加载 celery**：`import app` 即可验证（celery 惰性创建）

## 5. 日常巡检

| 检查项 | 方式 |
| :--- | :--- |
| 调度是否按期触发 | 定时任务页看"下次触发/最近执行"；连续 `dispatch_failed` 检查 worker/Redis |
| 任务积压 | 任务列表页统计卡片（pending 居高 → 扩 worker 实例） |
| 执行失败排查 | 任务详情 error 字段；worker/beat 进程日志 |
| 调度循环存活(local) | API 日志出现 `local 周期调度循环已启动`；无该行检查 `scheduler_enabled` |

## 6. 常见问题

**Q：改了 cron 多久生效？**
local 引擎立即（热更唤醒）；celery 引擎最迟 1 分钟（beat tick）。

**Q：beat 必须启动吗？**
local 引擎不需要。celery 引擎只在需要周期任务时启动，且全局单实例（多实例会重复触发，虽 `next_fire_at` 推进会自然收敛，仍建议单点）。

**Q：手动验证一个调度？**
定时任务页"立即触发"（`POST /task/schedules/{id}/trigger`），不影响周期节奏，生成任务可在任务列表查看。

**Q：worker 与 API 分开部署？**
可以。celery 引擎下 API（`app.py`）与 worker（`app_task.py`）可独立重启互不影响；定时任务管理页属 API 侧。
