# 发布流程

镜像只含 Python 环境，代码/配置全部外挂；镜像 tag 自动取 `pyproject.toml` 的版本号。

## 0. 快速发布

```bash
# ① 改版本号：code/backend/server_py/pyproject.toml 的 version
# ② 构建并发布
deveops/运维脚本/2-主服务/build.sh --up
deveops/运维脚本/3-任务队列/build.sh --up
# ③ 看日志
~/a_apps/codebiu-base/server/ctl.sh logs
```

日常只改代码（不动依赖）：

```bash
deveops/运维脚本/2-主服务/update.sh
deveops/运维脚本/3-任务队列/update.sh
```

## 1. 约定

| 项 | 约定 |
| :--- | :--- |
| 版本号 | `主.次.修订`，与 pyproject.toml version、镜像 tag、`tag_doc/tag_x.x.x.md` 对应 |
| 分支 | `main(稳定) ← PR ← dev ← feature/* / fix/*` |
| 变更记录 | 每次发布新建 `tag_doc/tag_<版本>.md` |
| 数据库 | 含表结构变更时，发布前执行 `uv run alembic upgrade head`（见 [版本升级与数据库迁移](./版本升级与数据库迁移.md)） |

## 2. 发布步骤

### ① 构建与启动

```bash
git checkout dev && git pull && git checkout -b release/1.0.1
# 改 pyproject.toml version = 1.0.1
deveops/运维脚本/2-主服务/build.sh --up
deveops/运维脚本/3-任务队列/build.sh --up
```

自动完成：后端镜像 → 部署目录 → 外挂代码同步 → 前端 dist（旧版自动备份）→ 容器启动。

### ② 数据库迁移（有表结构变更时）

```bash
cd code/backend/server_py
uv run alembic current
uv run alembic upgrade head
```

### ③ 验证清单

- [ ] 登录/退出/Token 续期
- [ ] 核心页面（文件管理/知识库）增删改查
- [ ] 权限角色（403 拦截生效）
- [ ] AI 对话流式输出
- [ ] `ctl.sh logs` 无 ERROR

## 3. 回滚

```bash
# 后端：部署目录 .env 改回旧 tag（旧镜像未删除才有效）→ 重建容器
sed -i 's|^SERVER_IMAGE=.*|SERVER_IMAGE=base-server:1.0.0|' ~/a_apps/codebiu-base/server/.env
~/a_apps/codebiu-base/server/ctl.sh up

# 前端：换回自动备份的旧 dist
cd ~/a_apps/codebiu-base/server/nginx/html
rm -rf index && cp -r index_<上一版时间戳> index
~/a_apps/codebiu-base/server/ctl.sh restart nginx

# 数据库：用最近一次备份恢复（见《数据库运维》）
```

## 4. 发布纪律

1. **先备份后发布**：数据库备份 + 前端 dist（已自动备份）
2. **一次只发一个版本**；旧镜像至少保留上一个版本
3. 含**数据库结构变更**的版本，发布前必须验证旧数据兼容
4. 发布后 30 分钟内观察日志：`~/a_apps/codebiu-base/server/ctl.sh logs`
5. 配置变更同步更新对应套件的 `deploy.env`
