# 发布流程

基于统一脚本体系（[deveops/运维脚本/docker_dev](../运维脚本/docker_dev/)）：镜像只含 Python 环境，代码/配置全部外挂，镜像 tag 自动取 `pyproject.toml` 的版本号。

## 0. 快速发布（TL;DR）

```bash
# ① 改版本号: code/backend/server_py/pyproject.toml 的 version（即镜像 tag）
# ② 一键构建+部署+重启
./deveops/运维脚本/docker_dev/build_all.sh
# ③ 观察日志
~/a_apps/docker_deploy/ctl.sh logs
```

日常改代码（不动依赖）发布更快：`./deveops/运维脚本/docker_dev/update_code.sh`

## 1. 约定

| 项 | 约定 |
| :--- | :--- |
| 版本号 | `主.次.修订`，与 pyproject.toml version、镜像 tag、`doc/tag_doc/tag_x.x.x.md` 对应 |
| 分支 | `main(稳定) ← PR ← dev ← feature/* / fix/*` |
| 变更记录 | 每次发布新建 `tag_doc/tag_<版本>.md`；下版本候选记入 `tag_todo.md` |

## 2. 发布步骤

### ① 冻结与构建

```bash
git checkout dev && git pull && git checkout -b release/1.0.1
# 改 code/backend/server_py/pyproject.toml 的 version = 1.0.1

./deveops/运维脚本/docker_dev/build_all.sh
#   可选: SKIP_WEB=1 跳过前端 / SKIP_SERVER=1 跳过后端 / DEPLOY_DIR=... 换部署目录
```

自动完成：后端镜像（`base-server:1.0.1` + latest）→ 部署目录初始化 → 外挂代码同步（src/config/public）→ 前端 dist 导出（旧版自动备份为 `index_时间戳`）→ 容器重启。

### ② 验证清单

- [ ] 登录/退出/Token 续期
- [ ] 核心页面（文件管理/知识库）增删改查
- [ ] 权限角色（403 拦截生效）
- [ ] AI 对话流式输出
- [ ] `ctl.sh logs` 无 ERROR

### ③ 正式发布

```bash
git checkout main && git merge release/1.0.1
git tag v1.0.1 && git push origin main --tags
# 生产机: 同步代码后同样执行 build_all.sh
#   离线环境: image_manager/export_docker_compose_images.sh 导出 → 拷贝 → load 脚本导入
# 登记 tag_doc/tag_1.0.1.md
```

## 3. 回滚

```bash
# 后端: 部署目录 .env 改回旧 tag（旧镜像未删除才有效）→ 重建容器
sed -i 's|^SERVER_IMAGE=.*|SERVER_IMAGE=base-server:1.0.0|' ~/a_apps/docker_deploy/.env
~/a_apps/docker_deploy/ctl.sh up

# 前端: 换回自动备份的旧 dist
cd ~/a_apps/docker_deploy/nginx/html
rm -rf index && cp -r index_<上一版时间戳> index
~/a_apps/docker_deploy/ctl.sh restart nginx

# 数据库: 用最近一次备份恢复（见《数据库运维》，破坏性变更发布前必须先备份）
```

## 4. 发布纪律

1. **先备份后发布**：数据库备份 + 前端 dist（`DIST_MODE=备份` 已自动）
2. **一次只发一个版本**，禁止跨版本连发；旧镜像至少保留上一个版本
3. 含**数据库结构变更**的版本，发布前必须验证旧数据兼容
4. 发布后 30 分钟内观察日志：`~/a_apps/docker_deploy/ctl.sh logs`
5. 涉及配置文件变更的，同步更新文档与 `deploy.env`
